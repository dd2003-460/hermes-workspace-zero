# 1-loop - Planning / Discussion

## 读取顺序

1. `../AGENTS.md`
2. `README.md`（本文件）
3. 双脑原则.md → 主脑.md → 副脑.md

## 这一层的边界

- 只讨论和主脑、副脑有关的原则收敛
- 只把判断推进到"原则是否成立、是否该进入执行"
- 不做执行、不写业务文件、不展开多余步骤

## 副脑轮次协议（四阶段）

每个 cron 副脑每轮必须走完这四个阶段，按顺序：

### 阶段 1：动机追问
- 我为什么在这里？上次做了什么？卡在哪？
- 我的动机是什么？服务于什么更大目标？
- 我的质量缺口在哪？什么盲区我看不到？
- **对标检查**：产出达到世界顶尖可扩散水平了吗？

### 阶段 2：目的驱动搜索
- 带着具体问题找工具/方法，不泛泛浏览
- "我需要解决 X，因为 Y 不够，原因是 Z"

### 阶段 3：停机判断
- 本轮有新产出吗？（不是重复上次）
- 有可执行判断吗？（推 or 不推）
- 无新增 → 标记"本轮无新增"，不硬写

### 阶段 4：状态更新
- 写入 notes/output.md / questions.md（如有追问）
- 置信度 > 0.6 + 可执行判断 → 标记"推荐转执行"

## 双向追问机制

副脑问 → 主 session 回答 + 反问。不是汇报，是对话。

## Sub 执行派发

1-loop 完成 + 停机判断确认后，才进入 2-loop 派执行 sub。
