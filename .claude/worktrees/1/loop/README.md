# Loop Architecture Template

这是一个两层 loop 工作流模板。

## 顶层设计

- `1-loop` 是 planning / relay 层。
- `2-loop` 是 execution / verify 层。
- 全局规则放在仓库级，不塞进 `2-loop`。
- 每次 loop 只能盯一个具体任务。
- 工具和辅助文件要放在自己的目录里，不影响其他部分。

## 全局原则

1. 先遵守 `agents + 步骤确认`。
2. 按索引读，不要为了省事跳过该读的文档。
3. 状态必须显式。每轮都要知道自己在哪、读哪个状态文件、写哪个状态文件。
4. 严格遵循 loop 对应文档，不把口头理解当规则。
5. 如果任务要探索、讨论、检查、建议或执行，就选定具体任务路径，并一直沿着它走。

## 文档放置

- 仓库级契约和模板意图：这个文件。
- 仓库共享原则：`prompt-template.md`。
- `1-loop/`：`双脑原则.md`、`主脑.md`、`副脑.md`。
- `2-loop/`：只放执行步骤文档。
- 任务级 / 项目级状态、工具、产出：放在自己的归属目录里。

## 状态路径

- 每个任务都应该显式声明状态读写路径。
- 读取路径和写回路径要完整，不要只说“已更新状态”。
- 如果是项目任务，状态跟着项目走；如果是根级共享任务，也要说明为什么放在根级。

## 上传意图

这个布局是给 GitHub 作为 template repository 用的，目标是让新用户直接复制结构，而不是继承一堆无关的执行遗留物。
