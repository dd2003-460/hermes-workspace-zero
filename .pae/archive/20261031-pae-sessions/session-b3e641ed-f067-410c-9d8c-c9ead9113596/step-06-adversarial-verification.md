# Step 06 — 对抗式 arena 核验循环（idea 核验 + 反追问，直到瓶颈）

## 目标
落实用户硬要求：所有 idea（D23 五命题 / 产业链事件信号 / 各 regime 博弈策略假设）必须严格找 arena 核验条件和有效性，且不能盲目相信核验判断——Lead 主动找 arena 核验结论的问题，反驳追问，直到碰到「数学理论瓶颈」或「个人信息搜集瓶颈」才终止。这是 step 05 验收之上的第二道对抗门禁（对应 04.5 反方复核 + arena 交叉核验）。

## 涉及文件
- 只读对象：
  - step 05 验收通过的 arena 各轮产出（T3/T4/T5 的核验结论文件）
  - `market-alpha/backtest-sop.md`（step 02 产出：核验结论若涉统计判据，须对照护栏条款）
  - `projects/金融/quant-capital-flow/tasks/state.md`（toy model 教训作为已知反例库：F/M 恒胜 S 是结构问题，核验时优先攻击同类结构假设）
- 产出：
  - 每个 idea 一份对抗记录 `market-alpha/loop-artifacts/stages/06/adversarial-<idea-id>.md`：逐轮「arena 结论 → Lead 反驳点 → arena 回应 → 新问题」，终止时写「终止原因 ∈ 瓶颈集 + 证据」。
  - 汇总表 `market-alpha/loop-artifacts/stages/06/06review.md`：idea × 核验轮数 × 终止瓶颈 × 结论置信度（conf 0-1）× 是否进入回测（进入 / 否决 / 降级为候选）。

## 做法
1. **反驳清单先行**：对每个 idea 的 arena 核验结论，Lead 按固定攻击序生成反驳点（每次核验 ≥1 条，从以下选，不得跳过前序）：
   - 数据口径：核验用的数据源是否有发布戳陷阱 / 量级陷阱（对照 backtest-sop 防前视节）？
   - 多重检验：结论是否把 p<0.05 当有效？是否计入 trial count（对照 BH-FDR/DSR 条款）？
   - 结构反例：是否重蹈 toy model 覆辙（把参数调优当结构有效）？
   - 方向映射：先验方向（如拥挤→反转）是否被样本内悄悄翻转过？
   - 文献锚点：引用的论文/数据源是否真实存在（grep 路径或 arXiv API 回查，编造引用 = 一票否决）。
2. **追问循环**：每轮把反驳点发给 arena 核验，记录其回应；回应若引入新事实（新数据/新文献），再对其新事实执行第 1 条攻击序。循环终止条件（必须二选一，写进记录）：
   - **数学理论瓶颈**：arena 给出可引用的数学边界（定理/引理 + 出处），Lead 无法用更一般的构造反驳——记录定理出处。
   - **个人信息搜集瓶颈**：所需信息属私人账户/付费/未公开（如 Level-2 逐笔、私人机构调研），公开渠道穷举（≥3 个独立公开源）后确认拿不到——记录穷举清单。
   - 禁止以「arena 说没问题」为终止理由（那正是用户点名要防的盲信）。
3. **裁决落盘**：每个 idea 最终状态三选一：进入回测（step 07 输入）/ 否决（负结果交付物，记录否决证据）/ 降级候选（证据不足，记入 decomposition 空缺清单，不阻塞主线）。
4. 全程每轮 commit + push（arena 侧产出 push 到 market-alpha 仓，Lead 侧对抗记录同仓 `loop-artifacts/stages/06/`）。

## 验收标准（可机器检查）
1. 每个进入核验的 idea（D23 五命题 + T4 事件信号 + T5 策略假设，合计 ≥8 项）有独立对抗记录文件，grep "终止原因" 可命中。
2. 每条终止原因 ∈ {数学理论瓶颈（含定理/文献出处）, 个人信息搜集瓶颈（含 ≥3 个独立公开源穷举清单）}，无第三种措辞（如 "arena 确认通过" 出现即不达标）。
3. 每个 idea 的核验轮数 ≥1 且每个 idea 的 Lead 反驳点 ≥1 条（反驳点原文在记录内）。
4. `06review.md` 汇总表行数 = 核验 idea 数，每行 conf ∈ [0,1] 且处置 ∈ {进入回测, 否决, 降级候选}。
5. 进入回测的 idea 在 step 07 的预注册输入清单中出现（交叉引用可 grep）。
