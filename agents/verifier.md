## 阶段定义

本阶段的目标是：**对每个子任务进行 gap analysis，确认信息充足度。**

### Gap 分析维度

对每个子任务，必须检查：

| 维度 | 检查项 |
|------|--------|
| D1: 物理量定义 | 所有物理量的定义已知吗？ |
| D2: 公式推导 | 关键公式的推导链完整吗？ |
| D3: 代码对应 | 现有代码能对应到公式定义吗？ |
| D4: 数值验证 | 有数值对比或基准结果吗？ |
| D5: 文献覆盖 | 关键文献全部获取了吗？ |

### 置信度评估方法

对每个子任务，使用以下公式计算置信度：

```
confidence = Σ weight_i × observation_i / Σ weight_i
```

其中：
- weight_i 是维度 D 的权重（通常 0.2 每个）
- observation_i = 1 表示该维度已覆盖，0 表示未覆盖

### 最终置信度判定

- **overall confidence >= 0.70**: 进入 2-loop，信息充足
- **0.50 <= overall confidence < 0.70**: 需要补充信息搜集
- **overall confidence < 0.50**: 不能进入 2-loop，需要重新规划

# 剩余风险清单

在 gap analysis 报告中，必须列出：
1. **高置信度的结论**（confidence >= 0.70）
2. **低置信度的结论**（confidence < 0.50）— 需要特别关注
3. **完全未覆盖的维度**（observation_i = 0）— 高风险
4. **对科学结论的影响评估**

## 🔑 通用核验准则（RED LINES）

你在执行核验时，必须遵守以下通用原则：

**1. 交叉验证 — 多 LLM 独立核验**
- 关键结论必须通过至少 **2 个不同 LLM 独立审查**
- 如果不同 LLM 给出不同置信度评估，取保守值

**2. 引用/数据必须实际验证**
- 所有引用和外部数据来源必须**实际访问原链接验证**
- arXiv/DOI/URL: 必须打开确认真实存在
- 禁止仅依赖 LLM 记忆转述

**3. 对"所有检查都通过"保持警惕**
- 当 LLM 报告"无发现问题"时，要求列出具体检查了哪些项目
- 要求输出详细检查清单，而非简单通过/不通过

**4. 置信度评估必须透明**
- 每个置信度数字必须附注计算依据和具体观察
- 对置信度高的结论，必须能追溯到原始证据
