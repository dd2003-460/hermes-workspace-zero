Efficiency factor definition: Since classification is "产出下面的效率因子" (efficiency factor under output), define:

产出 = 有效 token 数 / 时间 (goodput under SLO). Cost side not decomposed here, so efficiency factor η is a dimensionless multiplier applied to theoretical/ideal output to get actual output. Break down:

η_total = η_batch × η_mix × η_cache × η_len × η_scale × η_util

Where:

η_batch: 批并行效率 = 实际聚合吞吐 / (单流吞吐 × 并发数) — measured: A100 c=64: 2429/(79.664)=0.477; H100 PCIe c=64: 4515/(10464)=0.678; A6000 c=64: 1727/(4264)=0.643; L40S 1887/(4864)=0.614; 5090 agentic c=64 1683/(single? 57.5 at c16 ... hmm need single-stream 5090 from paper maybe 89 t/s per user; use other).
η_mix: 混合负载效率 = 混合负载吞吐 / 同硬件纯 decode 吞吐 (or weighted baseline). e.g., vLLM issue #44703: long_decode 2359, long_prefill_8k 652 (28%), repeated_prefix 1261 (53%). That's a strong "混批损耗".
η_cache: 缓存命中率 (prefix cache hit) effect on prefill; real-world 95.7% token hit but collapses; Mooncake 28-49%; Microsoft Azure benchmark: A100 chat 75%, classification 97%, code 1% hit.
η_len: 上下文长度效率 = throughput at long ctx / at short ctx. e.g., 2K→16K: Pro6000 −38.7%, H100 −63.7%, H200 −46.5%; 5090 doubling context halves TPS.
η_scale: 多卡/多副本扩展效率: 8x PRO6000 15713 vs 8*3140=25120 → 63%; 2x 5090 TP: 1.14–1.57x; CloudRift multi-GPU with TP: 1.45-1.72x H100 advantage.
η_util: GPU 利用率 / duty cycle: real production KV cache utilization 30-70%, queue depth swings; GPU util from Spheron 45-87% by concurrency; A100 roofline repo says at c=64 neither roof saturated, 18/26 ms overhead (η_overhead=31%).
