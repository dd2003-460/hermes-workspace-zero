## 2. 结构问题归因（为什么 agent 不按流程走）

### 问题 1：信号淹没在噪声中（核心问题）

218 行中，agent 建 goal 时真正需要执行的核心指令（A 类纯 A 部分）约 83 行（38%）。其余 62% 是执行级细节（B）和教学/解释内容（C）。agent 读取时无法区分"现在必须做的"和"以后才需要的"和"只是解释背景"，导致：
- 注意力被 §2.4.1 结构化输出派发（38 行，含 token 对比表、KV-bound 解释、四种输出形状注册表）分散——这是一篇完整的 skill 文档，不是 goal 创建指令
- §2.4 Arena 仓库选择（31 行）含大量执行级细节（GitHub App 授权、pfb 中转、泄漏面实验结论），agent 在创建 goal 时不需要知道这些

### 问题 2：章节编号混乱，层级关系不清

- §3 出现在 §1 之前（文件开头就是 §3 Goal 描述模板）
- §1 的标题是"质量原则"但没有 §1 总标题，直接从 §1.1 开始
- §2.4 和 §2.4.1 夹在 §2.1 和 §2.3 之间，编号不连续
- 存在空 `##` 节（行 191-192），是编辑残留
- agent 无法从结构上判断阅读优先级

### 问题 3：指令与解释混杂

同一节内混合了：
- 硬规则指令（"必须"、"禁止"、"→"流程）
- 教学性解释（"为什么能极大减少 decode 负担"、KV-bound 原理、token 对比表）
- 历史变更记录（"2026-10-26 修正"、"旧认知已作废"、"用户实证"）
- 实验结论引用（"泄漏面结论 conf 0.95"）

agent 面对的是平铺的文本流，没有视觉/结构上的优先级区分。

### 问题 4：§3.0 自主探索原则过重（39 行，17.9%）

这一节混合了：
- 核心原则（循环内核、P-1/P-2/P-3 优先级）——属于 A 类
- 标准链路 actions 序列（中转模式动作序列 7 步）——属于 B 类，应在 arena-loop-pipeline.md 中
- 硬规则（验收降级条款等）——属于 A 类

39 行里约一半是执行链路细节，不应在 goal 模板中。

### 问题 5：§2.4.1 结构化输出派发是完整 skill 文档（38 行，17.4%）

包含：
- skill 位置路径
- 四种输出形状定义（router/brief/advisor/ticket）
- 三种派发方式（model 后缀/HTTP 头/软约束）
- token 对比表 + KV-bound 原理解释
- 推荐场景

这是一篇独立的 skill 文档，不应内嵌在 goal 模板中。goal 模板只需一行指针："决策型子任务 → structured-dispatch skill"。

### 问题 6：重复内容

- §1.2 和 §3.2 都有"验收标准示例"（预测类/调研类/实验类），内容几乎相同
- §1.4 防遗忘机制列的 5 项与 §3 模板格式的 5 字段重复
- §2.0 的 6 步链路在 arena-loop-pipeline.md 中已有完整定义

## 5. 结论

goal-template.md 当前 218 行中，约 60% 是执行级细节和教学性内容，只有约 40% 是建 goal 时真正需要的核心指令。agent 不按流程走的根本原因是**信号-噪声比太低**：核心指令被 skill 文档、执行链路细节、历史变更记录淹没，agent 无法快速定位"现在该做什么"。

推荐方案：瘦身为"定位器"——只留五字段模板 + 阶段顺序 + SOP 指针，执行细节外移到对应 SOP 文档，目标 60-80 行。
