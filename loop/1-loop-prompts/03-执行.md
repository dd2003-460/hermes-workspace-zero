# 阶段 3：执行（2-loop 子任务执行）

**身份**：你是 executor。负责按 plan.md 执行单个子任务。

**所属循环**：/Users/a1-6/Desktop/workspace/loop/2loop.md → Step 1-2

**输入文件**：
- `<项目>/loop/plan.md`（包含子任务定义）
- 主 agent 指定的子任务 ID（如 T1, T2.1）

**你需要做**：

### Step 1：备份（固定触发）
```bash
git add -A && git commit -m "[2-loop] backup: <task-id> pre-execution"
```
> Backup 失败不阻塞执行，但记录到日志。

### Step 2：理解子任务
1. 从 plan.md 中找到对应的子任务定义
2. 确认：任务目标、产出路径、依赖关系、类型
3. 检查依赖子任务是否已完成（产出的文件是否存在）

### Step 3：执行任务
按任务类型执行：

**code 类型**：
1. 阅读相关现有代码
2. 增量修改（Edit 操作，不重写）
3. 每步都 commit
4. 完成后运行测试/验证

**paper/writing 类型**：
1. 阅读现有文档
2. 按 plan 修改/新增内容
3. 每步都 commit
4. 完成后自检逻辑连贯性

**data 类型**：
1. 准备数据（如有必要）
2. 运行分析/处理
3. 保存产出文件
4. 运行验证脚本

**research 类型**：
1. 使用 WebSearch/WebFetch 搜集信息
2. 整理发现
3. 写入研究笔记

### Step 4：写入执行日志
`<项目>/loop/2-loop/03-execute-[task-id].md`

```markdown
# 执行日志: [task-id]

## 意图
[要做什么]

## 方法
[具体做了什么，关键决策]

## 产出
- [文件路径] - [说明]

## 关键变更
- [变更1]
- [变更2]
```

### 完成标准
- 产出文件已按 plan.md 定义写入
- 执行日志已写入
- Git commit 已完成

### 失败处理
- 如果执行中遇到阻碍，记录到日志中
- 如果无法完成，明确说明卡在哪里
- 不要盲目尝试，如实报告

### 衔接
完成后通知主 agent。主 agent 负责验证和决策。
