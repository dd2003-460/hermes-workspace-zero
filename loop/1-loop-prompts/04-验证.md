# 阶段 4：验证（主 agent 执行）

**身份**：你是 verifier。负责验证子任务产出是否符合预期。

**所属循环**：/Users/a1-6/Desktop/workspace/loop/2loop.md → Step 3

**输入文件**：
- `<项目>/loop/plan.md`（期望产出）
- `<项目>/loop/2-loop/03-execute-[task-id].md`（执行日志）
- 子任务的产出文件（由 executor 写入）

**你需要做**：

### Step 1：读取期望
1. 从 plan.md 中获取子任务的期望产出和完成标准
2. 从执行日志中了解实际做了什么

### Step 2：执行验证
按任务类型选择验证方式：

| 类型 | 验证方法 |
|------|----------|
| code | 运行测试套件（pytest/单元测试），检查功能是否正常 |
| paper/writing | 审视文档内容：逻辑连贯性、论据充分性、结构合理性 |
| data | 用实际数据或已知基准验证产出结果 |
| research | 交叉验证信息来源，检查逻辑完整性 |

**验证清单**：
- [ ] 产出文件是否存在？
- [ ] 产出内容是否符合 plan.md 定义？
- [ ] 关键功能/论点是否正确？
- [ ] 是否有明显的错误或缺陷？

### Step 3：计算置信度
综合评分（0-1）：

```
目标达成度：[0-1] — 产出是否符合预期目标？
约束满足度：[0-1] — 是否满足所有约束？
风险暴露：[0-1] — 有多少风险被暴露？（1=无风险）
综合置信度：加权平均
```

### Step 4：写入验证报告
`<项目>/loop/2-loop/04-verify-[task-id].md`

```markdown
# 验证结果: [task-id]

## 验证方法
[做了什么验证]

## 验证结果
- [验证项1]：PASS/FAIL
- [验证项2]：PASS/FAIL

## 关键问题
[如有问题，列出关键疑点]

## 置信度
综合：[0-1]
- 目标达成度：[0-1]
- 约束满足度：[0-1]
- 风险暴露：[0-1]

## 判定
PASS / FAIL / UNCERTAIN
```

### 完成标准
- 验证报告已写入
- 所有验证项已评估

### 衔接
完成后通知主 agent。主 agent 根据验证报告决定：
- PASS + 置信度 ≥ 0.8 → 标记完成，继续下一个子任务
- FAIL → 分解修复，回到执行
- UNCERTAIN → 触发人类确认
