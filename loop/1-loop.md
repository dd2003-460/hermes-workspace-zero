# 1-loop — Planning（全局规划流程）

**原则**：任务要求→目标澄清→分解→信息搜集→核验→决策。让任务可以被正确执行。

## 标准化输入：项目名-task.md(位于这个项目的根目录)

每次 1-loop 启动，先写这个文件（如果不存在）：

```json
{
  "requirement": "要完成什么",
  "background": "相关背景",
  "existing_info": ["已知条件、已有文件"],
  "constraints": ["时间、工具、资源限制"],
  "priority": "planning | immediate"
}
```

## 六个阶段

### 阶段 1：任务澄清
**输入**：项目名-task.md
**输出**：完整清晰任务定义（
**检查**：任务边界、约束条件、已有条件、失败标准

### 阶段 2：目标澄清
**输入**：任务定义
**输出**：验收标准（成功的判定）
**检查**：可验证标准、质量要求、硬约束、可妥协部分

### 阶段 3：任务分解
**输入**：验收标准
**输出**：子任务列表（每个有输入→输出→验证→回滚→置信度 [0,1]）
**检查**：不依赖外部即可执行、DAG 有向无环、每步可独立验证

### 阶段 4：信息搜集
**输入**：子任务列表
**输出**：工具清单 + 新颖性评估 N0-N3
**检查**：工具可用、数据可访问、背景知识充足、查重完成

### 阶段 5：完备核验
**输入**：工具清单 + 子任务列表
**输出**：gap_analysis.json
**维度**：理论完整性(高)、工程可行性(高)、工具就绪(中)、方向正确性(高)、可回滚性(中)

### 阶段 6：决策
**输入**：gap-analysis.json
**输出**：decision.md（enter_2loop | continue_1loop）


## 转移标准：进入 2-loop



**软条件**：
- 每步粒度：一个 agent 不超出设定上下文长度(看设定长度,有时候是32k,为保证对接,单步骤要在长度基础减去全局原则,前后对接的上下文长度)即可独立完成
- 没有已知的更优替代方案被遗漏
- 连续两轮 1-loop gap_analysis 变化 < 20%（最优化的收益已被提取）
- 下次迭代的预期增益 < 执行错误成本

## 双脑

- **主脑**：说清任务、目标、状态路径。接收副脑质疑。判断是否进入 2-loop。
- **副脑**：质疑主脑、找缺口、提醒不停止。每轮必出现。
- **不做什么**：不直接改文件、不替代 2-loop、不把一次回复当成结束
