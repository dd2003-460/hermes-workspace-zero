# 01-任务澄清（Stage 1）

**输入**：`task-spec.md`（位于项目根目录）
**输出**：`task-definition.md`（一句话任务定义，不超过 3 行）

---

## 操作步骤

### Step 1：读取并验证输入
从 `task-spec.md` 中提取以下字段：
```json
{
  "requirement": "要完成什么",
  "background": "相关背景",
  "existing_info": ["已知条件、已有文件"],
  "constraints": ["时间、工具、资源限制"],
  "priority": "planning | immediate"
}
```

**验证规则**：
- `requirement` 必须存在且非空
- 如果 `priority` 为 `immediate`，跳过 Step 2-5，直接进入 2-loop
- 如果 `priority` 为 `planning`，继续后续步骤

### Step 2：提取核心任务
从 `requirement` 字段中，提取一句话任务定义。
**约束**：不超过 3 行。

### Step 3：定义任务边界
明确回答以下问题（回答写入 `task-definition.md`）：
- 任务的范围是什么？（做什么）
- 任务的范围边界是什么？（不做什么）
- 失败的标准是什么？

### Step 4：列出约束条件和已有条件
从 `constraints` 和 `existing_info` 中提取并分类：
- **硬约束**：不可妥协的条件（如工具限制、时间限制）
- **已有条件**：已存在的文件、工具、数据

### Step 5：写入 task-definition.md
输出格式：
```markdown
# Task Definition
## 一句话任务（不超过3行）
[内容]

## 边界
- 范围：[做什么]
- 边界：[不做什么]

## 失败标准
- [列出失败的标准]

## 硬约束
- [列出不可妥协的条件]

## 已有条件
- [列出已存在的文件/工具/数据]
```

---

## 输出文件

**必须存在**：`task-definition.md`

---

## 前置依赖

读取 `task-spec.md` → 如果不存在，先执行 Step 1-4 生成

---

## 后置依赖
