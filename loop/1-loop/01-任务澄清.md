# 01-任务澄清（Stage 1）

**输入**：`task-spec.md`（位于项目根目录）
**输出**：`task-definition.md`（一句话任务定义，不超过 3 行）

---

## Agent 使用规范

Commander **禁止亲自执行底层分析**。所有需要外部信息、公式推理、代码审查的任务必须通过 Agent 工具分发：

| 场景 | 使用 Agent | 原因 |
|------|-----------|------|
| 读取外部文献/文档并总结 | 通过 `agent` 工具调用 `Explore` 或 `general-purpose` | Commander 无法直接阅读外部文件时通过 Agent 拉取 |
| 物理公式推导与验证 | `general-purpose` Agent | 复杂物理推理需要专业 Agent 处理 |
| 已有代码/脚本的内容审查 | `Explore` Agent | 需要遍历多个文件确认 API 和实现 |

**强制要求**：
- 如果 `requirement` 涉及外部文献或已有代码，Step 1 中必须通过 Agent 搜集信息
- Commander 只做**综合和决策**，不做信息搜集或公式推导

---

## 操作步骤

### Step 1：读取并验证输入（Agent 辅助）
**通过 Agent 执行**：读取 `task-spec.md`，提取以下字段：
```json
{
  "requirement": "要完成什么",
  "background": "相关背景",
  "existing_info": ["已知条件、已有文件"],
  "constraints": ["时间、工具、资源限制"],
  "priority": "planning | immediate"
}
```
- 如果 `existing_info` 指向外部文件或代码，通过 Agent 验证文件存在性和内容
- 通过 Agent 搜索 GitHub 或本地仓库确认是否有现成实现

**验证规则**：
- `requirement` 必须存在且非空
- 如果 `priority` 为 `immediate`，跳过 Step 2-5，直接进入 2-loop
- 如果 `priority` 为 `planning`，继续后续步骤

### Step 2：提取核心任务（Agent 辅助）
**通过 Agent 辅助**：如果任务涉及已有代码或文献，先通过 Agent 了解背景，再提取一句话任务定义。
**约束**：不超过 3 行。

### Step 3：定义任务边界
明确回答以下问题（回答写入 `task-definition.md`）：
- 任务的范围是什么？（做什么）
- 任务的范围边界是什么？（不做什么）
- 失败的标准是什么？

### Step 4：列出约束条件和已有条件（Agent 辅助）
**通过 Agent 执行**：验证 `existing_info` 中的文件和工具实际可用：
- 通过 Agent 检查文件存在性
- 通过 Agent 检查工具/依赖是否已安装
- 通过 Agent 搜索是否有相关实现

从 `constraints` 和 `existing_info` 中提取并分类：
- **硬约束**：不可妥协的条件（如工具限制、时间限制）
- **已有条件**：已存在的文件、工具、数据

### Step 5：写入 task-definition.md
输出格式：
```markdown
# Task Definition
## 一句话任务（不超过3行）
[内容]

## 边界
- 范围：[做什么]
- 边界：[不做什么]

## 失败标准
- [列出失败的标准]

## 硬约束
- [列出不可妥协的条件]

## 已有条件
- [列出已存在的文件/工具/数据]
```

**必须存在**：`task-definition.md`
