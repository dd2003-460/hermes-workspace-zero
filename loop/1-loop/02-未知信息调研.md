# 02 未知信息调研（逐个未知词派 subagent 调研）

<!-- origin: ai -->

## 输入

- 上一阶段交付物：`loop-artifacts/01-r1.md` / `01-r1.json`。
- 其中 `unknown` 字段里的**每一个词语**，就是一个独立的待调研项。
- 灵魂默认决策画像（`AGENTS.md` 默认偏好）。

## 本阶段交付物（每阶段只一对文件，命名 `0x-rx`，链式传递）

- `loop-artifacts/02-r1.json`：**你只需写这个**——每个未知词调研后产出的字段（用 `ralph field-apply <项目> loop-artifacts/02-r1.json` 落盘）。
- `loop-artifacts/02-r1.md`：可读性 Markdown，**由 `ralph render` / field-apply 自动从 JSON 生成，你不必手写**。
- **下一阶段（02.5）的输入就是本阶段的 `02-r1.json`**（需人读版看同目录 `.md`）。

## Commander 的工作（极简：只编排，不调研）

Commander 是**薄分发器**，几乎不干活：

1. 从 `01-r1.json` 的 `unknown` 字段取出每个未知词，逐个处理。
2. 对**单个未知词**，派一个窄调研 subagent，把「调研 prompt（见下）」连同该**单个未知词**一起交给它。
3. subagent 返回只含那一个字段的 JSON，Commander 用 `ralph field-apply <项目> <单字段文件>` 落盘。
4. 所有 `unknown` 词处理完即本阶段完成，** Commander 自己不写任何调研内容、不查证据**。

> 给主 agent 的提示只需：**命令 + 单个未知因素字段**。
> 示例：`ralph field-apply <项目> <文件>`，文件内仅 `{concept:"<单个未知词>", ...}`。

## 给 subagent 的调研 prompt（这才是真正的调研指令）

> 你只负责调研**一个**未知词。请直接联网搜索 **不加年份** 的关键词（描述事实本身，如「H100 HBM3e 带宽」「GPU 互联 NVLink 带宽」），拿到**当前最新**的官方规格 / 论文 / 基准 / 厂商文档。
> 产出**只含这一个字段**的 JSON，必须带回 `evidence_refs`（URL）与 `confidence`：
> `{concept, role:"未知", attribute, disposition:"confirmed"|"assumed_default", rationale, evidence_refs:[...], confidence, impact, reversible}`。
> 不要读无关文档，不要产出其他字段。

## 字段表怎么填（通过 `ralph field-apply`，禁止直接写 loop-state.json）

- 每个未知词调研完，写成一条字段 JSON，运行 `ralph field-apply <项目> <单字段文件>`：校验通过才原子落盘（按 `concept` 合并；`{"concept":"...","delete":true}` 删除）。
- 可累积多条后一次性 `field-apply`，但每条必须带 `evidence_refs`。

## 检查

- [ ] `unknown` 中每个词都已派 subagent 调研并带回 `evidence_refs`。
- [ ] 无未带证据的 `research_required` / `unknown` 字段残留。
- [ ] 调研引出的新未知已被消化（无 `pending`）。

## 分支

- 通过：输出 `advance` 进入 `02.5`（字段完整后也可等待运行时推进）。
- 等待人类：返回 `blocked_human`（仅限「项目/环境无答案、会改变硬可行性」的项）。

## 必须遵守

1. 阶段编号 `02`；重新调研用 `02-r2`。
2. **Commander 不调研、不查证据、不写调研内容**，只派 subagent + field-apply；调研指令在给 subagent 的 prompt 里。
3. 搜索不加年份，确保拿到最新结果。
4. 本阶段只做调研与证据补齐，**不做交叉验证**（交叉验证在 02.5）。
