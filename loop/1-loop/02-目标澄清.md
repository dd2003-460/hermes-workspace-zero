# 02-目标澄清（Stage 2）

**输入**：`task-definition.md`（来自阶段 1）
**输出**：`acceptance-criteria.md`（验收标准文件）

---

## Agent 使用规范

Commander **禁止亲自验证验收标准的可执行性**。每个验收标准必须通过 Agent 确认可被测试：

| 场景 | 使用 Agent | 原因 |
|------|-----------|------|
| 验证验收标准是否可测试 | `sub-brain` Agent（如果存在）或 `general-purpose` | 独立 Agent 质疑验收标准的完备性 |
| 物理公式验证 | `general-purpose` Agent | Agent 可以推导公式确认标准是否正确 |
| 代码验收标准 | `Explore` Agent | Agent 可以确认现有代码是否支持该验收 |

**强制要求**：
- 每个验收标准必须经过至少一个独立 Agent 的质疑/验证
- Commander 不做自证——验收标准通过后必须有 Agent 确认

---

## 操作步骤

### Step 1：读取任务定义
从 `task-definition.md` 中提取：
- 一句话任务
- 任务范围
- 边界

### Step 2：列出可验证的验收标准（Agent 质询）
基于任务定义，逐条列出验收标准。

**通过 Agent 执行**：将验收标准草案发送给 `sub-brain` Agent 进行质疑：
- "这个验收标准是否可独立验证？"
- "是否存在遗漏的验收维度？"
- "验收条件是否过于宽松或过严？"

**约束**：
- 每条标准必须可独立验证（是/否判定）
- 质量要求必须明确（如"世界顶尖可扩散水平"）
- 每个标准都必须对应一个可运行的测试或可审查的交付物

### Step 3：标记硬约束和可妥协部分（Agent 审查）
**通过 Agent 审查**：将标注结果发送给独立 Agent，确认硬约束没有被错误标记为可妥协。

对每个验收标准标注：
- **硬约束**：不满足则整体失败
- **可妥协部分**：不满足则质量降级但可交付

### Step 4：写入 acceptance-criteria.md
输出格式：
```markdown
# Acceptance Criteria
## 验收标准
1. [标准描述] — [硬约束/可妥协]
2. [标准描述] — [硬约束/可妥协]
...

## 质量要求
- [明确的质量标准，如"世界顶尖可扩散水平"]

## 硬约束（不可妥协）
- [列出]

## 可妥协部分（质量降级但可交付）
- [列出]
```

## 确认机制

完成本阶段后，必须在产出文件底部添加确认区块：

```
---
## ⚠️ 等待人类确认
请审阅以上目标设定和判定标准。
确认：在文件顶部写下 `CONFIRMED 1`（同意）或 `CONFIRMED 2` + 修改建议。
**AI 不可修改已确认区块中的任何内容。**
```

人类确认（`CONFIRMED 1`）后，方可进入下一阶段。

## 质询方法论（应用于目标澄清）

成璐的提问方式是**反复自我质询直到边界**：
1. 提出论点 → 反复质疑自己（不是问别人，是质询自己）
2. 分解定义到不同层面（如"男性数学比女性好"→ 生理层面、模因层面）
3. 检查定义的完备性（什么是完备？覆盖所有情况 = 完备）
4. 划定范围/边界条件（中国还是世界？什么年代？什么年龄段？）
