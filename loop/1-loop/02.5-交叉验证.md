# 02.5 调研后交叉验证（基于已有调研结果）

<!-- origin: ai -->

## 输入

- 上一阶段交付物：`loop-artifacts/02-r1.md` / `02-r1.json`（调研完成的字段与证据）。
- `loop-state.json` 中已调研、带 `evidence_refs` 的关键字段。
- 网页 LLM 清单与权威数据源（见下）。

## 本阶段交付物（每阶段只一对文件，命名 `0x-rx`，链式传递）

- `loop-artifacts/02.5-r1.json`：**你只需写这个**——结构化结果，含更新后的字段（矛盾处置、更新后的 `confidence`/`disposition`/`evidence_refs`），用 `ralph field-apply <项目> loop-artifacts/02.5-r1.json` 落盘。
- `loop-artifacts/02.5-r1.md`：可读性 Markdown，**由 `ralph render` / field-apply 自动从 JSON 生成，你不必手写**。
- **下一阶段（03）的输入就是本阶段的 `02.5-r1.md` / `02.5-r1.json`**。

## 本阶段要做什么

基于 02 的调研结果，逐字段交叉验证，检查矛盾与冲突：

1. **Commander 只派发 subagent**，自身不直接去问；每条待验证字段生成一张 builder 卡，**卡内嵌该字段的当前内容**（concept / attribute / disposition / evidence / rationale）作为参数。
 2. **subagent 拿字段内容去核验**：用 `WebSearch`（论文、官方规格、基准测试、厂商文档——自动化环境最可靠）为主，可用 `WebFetch` 抓**公开文本页**（`https://www.perplexity.ai/`、`https://arxiv.org/abs/<id>`、厂商规格页如 `nvidia.com/en-us/data-center/h100/`、`amd.com/.../instinct-mi300x`、`cloud.google.com/tpu/docs/...`）。**禁止对纯 JS 聊天页（chatgpt.com / claude.ai / gemini.google.com / grok.com / copilot.microsoft.com / arena.ai/agent / poe.com / bigmodel.cn / aistudio.google.com）做 WebFetch——这些页自动抓取返回空，会无限空转，只允许用 WebSearch 获取其公开信息。** 关键词不加年份，拿最新结果。
3. **比较与裁决**：不同 LLM / 来源之间是否矛盾冲突；更新字段的 `confidence`、`disposition`、`evidence_refs`、`rationale`（含矛盾说明）。
4. 产出交叉验证摘要，记录哪些字段被复核、哪些存在未决矛盾。

## 字段表怎么填（通过 `ralph field-apply`，禁止直接写 loop-state.json）

- 把更新后的字段写成 `02.5-r1.json`（列表，或 `{"fields":[...]}`），运行
  `ralph field-apply <项目> loop-artifacts/02.5-r1.json` 原子落盘（按 `concept` 合并）。

## 检查

- [ ] 每个关键调研字段经 ≥2 独立来源核验。
- [ ] 矛盾已记录并更新字段 `confidence` / 处置。
- [ ] 无未处置的核验冲突。

## 分支

- 通过：输出 `advance` 进入 `03`。
- 等待人类：返回 `blocked_human`（仅限会改变硬可行性的未决矛盾）。

## 必须遵守

1. 阶段编号 `02.5`；重新验证用 `02.5-r2`。
2. Commander 只派发，不直接去问；每张卡内嵌字段内容。
