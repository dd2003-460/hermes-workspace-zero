# 03-任务分解（Stage 3）

**输入**：`acceptance-criteria.md`（来自阶段 2）
**输出**：`task-decomposition.md`（子任务 DAG 列表）

---

## Agent 使用规范

任务分解阶段**必须通过 Agent 并行执行子任务的设计**。Commander 不单独完成每个子任务的详细设计：

| 场景 | 使用 Agent | 原因 |
|------|-----------|------|
| 子任务设计 | `general-purpose` Agent 并行 | 每个子任务由独立 Agent 设计，避免 Commander 上下文窗口限制 |
| DAG 依赖分析 | `sub-brain` Agent | 独立 Agent 发现依赖关系中的遗漏或循环依赖 |
| 并行策略评估 | `general-purpose` Agent | Agent 评估并行策略的可行性 |

**强制要求**：
- 每个子任务的设计必须经过至少一个 Agent 的审查
- DAG 必须由 Agent 验证无环
- Commander 做最终仲裁，不做逐个子任务的细节设计

---

## 操作步骤

### Step 1：分解为子任务（Agent 并行执行）
**通过 Agent 并行执行**：基于 `acceptance-criteria.md`，为每条验收标准启动一个 `general-purpose` Agent，将子任务设计任务分发出去。

**约束**：
- 每个子任务必须有明确的输入→输出→验证→回滚→置信度 [0,1]
- 不依赖外部即可执行
- DAG 有向无环（子任务间有明确的依赖关系）
- 每步可独立验证

### Step 2：定义子任务粒度
每个子任务必须满足：
- 一个 agent 不超出上下文设定长度即可独立完成
- 如果某个子任务过大，**通过 Agent 递归分解**直到满足粒度要求

### Step 3：构建 DAG 依赖图（Agent 审查）
**通过 `sub-brain` Agent 审查**：将初步 DAG 发送给 Agent，验证：
- DAG 无环
- 没有遗漏的依赖关系
- 并行机会未被浪费

明确标注：
- 每个子任务的依赖子任务（如果有）
- 无依赖的子任务可以并行执行

### Step 4：写入 task-decomposition.md（Agent 辅助整理）
**通过 Agent 辅助整理**：收集所有 Agent 返回的子任务信息，整合为统一的 DAG 格式。

输出格式：
```markdown
# Task Decomposition
## Subtask 1: [名称]
- 输入：[具体输入]
- 输出：[具体输出]
- 验证：[如何验证]
- 回滚：[如果失败如何回滚]
- 置信度：[0,1]
- 依赖：[子任务编号，无则为 null]

## Subtask 2: [名称]
...
```

## 确认机制

完成本阶段后，必须在产出文件底部添加确认区块：

```
---
## ⚠️ 等待人类确认
请审阅以上任务分解和依赖关系。
确认：在文件顶部写下 `CONFIRMED 1`（同意）或 `CONFIRMED 2` + 修改建议。
**AI 不可修改已确认区块中的任何内容。**
```

人类确认（`CONFIRMED 1`）后，方可进入下一阶段。

## 质询方法论（应用于任务分解）

成璐的提问方式是**反复自我质询直到边界**：
1. 提出论点 → 反复质疑自己（不是问别人，是质询自己）
2. 分解定义到不同层面（如"男性数学比女性好"→ 生理层面、模因层面）
3. 检查定义的完备性（什么是完备？覆盖所有情况 = 完备）
4. 划定范围/边界条件（中国还是世界？什么年代？什么年龄段？）
