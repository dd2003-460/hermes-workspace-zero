# 04-信息搜集（Stage 4）

**输入**：`task-decomposition.md`（来自阶段 3）
**输出**：`tool-inventory.md`（工具清单 + 新颖性评估 N0-N3）

---

## 操作步骤

### Step 1：为每个子任务识别可用工具
基于 `task-decomposition.md` 中的每个子任务，列出可用的工具/方法。

**约束**：
- 工具必须可用（已安装、可调用）
- 如果工具不可用，标记为"需要安装"并记录安装路径
- 不得只依赖"人工编写"——优先使用现成工具/脚本

### Step 2：评估背景知识是否充足
对于每个子任务，评估：
- 是否已有足够的背景知识来执行？
- 是否需要额外的文献、文档、代码参考？
- 如果需要，记录缺失的知识点

### Step 3：完成查重
对每个工具的可用性进行检查：
- 是否有现成的实现？
- 是否有更好的开源方案？
- 是否有 GitHub 上的最佳实践？

### Step 4：评估新颖性（N0-N3）
```
N0 - 已有实现，无需任何创新
N1 - 需要少量调整或组合
N2 - 需要中等程度的创新
N3 - 需要重大创新
```

### Step 5：写入 tool-inventory.md
输出格式：
```markdown
# Tool Inventory
## Subtask N: [名称]
- 可用工具：[工具列表]
- 工具可用性：[可用/需要安装/不可用]
- 背景知识：[充足/不足 + 缺失知识点]
- 查重结果：[是否有更好的实现]
- 新颖性：[N0-N3]

## 总体评估
- 工具就绪度：[complete|partial|missing]
- 阻塞项：[如有阻塞项，列出]
- 新颖性评估：[N0-N3]
```
