# 04-信息搜集（Stage 4）

**输入**：`task-decomposition.md`（来自阶段 3）
**输出**：`tool-inventory.md`（工具清单 + 新颖性评估 N0-N3）

---

## Agent 使用规范

信息搜集阶段**必须通过 Agent 工具执行**，Commander 不亲自进行文献检索或代码搜索。

| 场景 | 使用 Agent | 原因 |
|------|-----------|------|
| 外部文献检索（arXiv、Google Scholar） | `Explore` Agent（浏览器控制） | 通过浏览器控制搜索并抓取文献摘要/全文 |
| GitHub 代码搜索 | `Explore` Agent（浏览器控制） | 通过浏览器搜索 GitHub 开源实现 |
| 工具可用性验证 | `general-purpose` Agent | Agent 检查系统环境、依赖安装状态 |
| 背景知识验证 | `general-purpose` Agent | Agent 确认现有知识是否覆盖子任务需求 |

**强制要求**：
- 所有外部文献搜索必须通过浏览器控制 Agent 执行，不得仅依赖 Commander 记忆
- 新颖性评估必须经过至少一个 Agent 确认（Google Scholar/GitHub 搜索）
- Commander 不做搜索操作——只评估 Agent 返回的结果

**浏览器控制说明**：通过 `Explore` Agent 的浏览器控制能力，可以：

### 资源搜索
1. 搜索 Google Scholar / arXiv / Semantic Scholar 获取相关文献
2. 抓取文献摘要和关键公式
3. 搜索 GitHub 上的开源实现

### 🔑 核心能力：与 LLM 讨论（**重点强调**）
> **浏览器控制的真正强大之处不是搜索，而是通过 LLM 的推理能力辅助决策。**
4. **向 LLM 询问方案选择**：将问题分析后发给 LLM，讨论多种方案各自的优劣，利用 LLM 的推理能力发现隐藏的权衡因素
5. **让 LLM 检查疏漏**：将已完成的分析发给 LLM，请求它扮演"批评者"角色，检查是否有遗漏的假设、错误的推理、被忽略的边界条件
6. **交叉验证结论**：将不同来源的信息发给 LLM，请求它判断是否存在矛盾或一致趋势
7. **讨论物理直觉**：当遇到难以用公式表达的概念性问题时，可以与 LLM 讨论物理直觉和概念框架

**为什么这个能力最重要**：LLM 的推理和模式识别能力远超 Commander 记忆。一个有足够上下文（文献摘要、公式、代码片段）的 LLM 可以发现人类忽视的关联、推导出新的洞察、指出逻辑漏洞。这是 Commander 独自工作无法获得的。**在关键决策点，必须利用浏览器控制向 LLM 提问，利用其推理能力辅助判断。**

## 操作步骤

### Step 1：为每个子任务识别可用工具（Agent 执行）
**通过 Agent 执行**：为每个子任务启动一个 `Explore` Agent，搜索可用的工具/方法。

**约束**：
- 工具必须可用（已安装、可调用）
- 如果工具不可用，标记为"需要安装"并记录安装路径
- 不得只依赖"人工编写"——优先使用现成工具/脚本

### Step 2：评估背景知识是否充足（Agent 辅助）
**通过 Agent 评估**：将子任务描述发送给 `general-purpose` Agent，确认：
- 是否有足够的背景知识来执行？
- 是否需要额外的文献、文档、代码参考？
- 如果需要，记录缺失的知识点

### Step 3：完成查重（浏览器控制 Agent 执行）
**通过 `Explore` Agent（浏览器控制）执行**：
- 搜索 GitHub 是否有现成实现
- 搜索 Google Scholar 是否有更好的开源方案
- 搜索 GitHub 上的最佳实践

### Step 4：评估新颖性（N0-N3）（Agent 确认）
**通过 Agent 确认**：将查重结果发送给 `general-purpose` Agent，确认新颖性评估。

```
N0 - 已有实现，无需任何创新
N1 - 需要少量调整或组合
N2 - 需要中等程度的创新
N3 - 需要重大创新
```

### Step 5：写入 tool-inventory.md（Agent 辅助整理）
**通过 Agent 辅助整理**：收集所有 Agent 返回的信息，整合为统一的 tool-inventory 格式。

输出格式：
```markdown
# Tool Inventory
## Subtask N: [名称]
- 可用工具：[工具列表]
- 工具可用性：[可用/需要安装/不可用]
- 背景知识：[充足/不足 + 缺失知识点]
- 查重结果：[是否有更好的实现]
- 新颖性：[N0-N3]

## 总体评估
- 工具就绪度：[complete|partial|missing]
- 阻塞项：[如有阻塞项，列出]
- 新颖性评估：[N0-N3]
```
