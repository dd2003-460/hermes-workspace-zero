# 05-完备核验（Stage 5）

**输入**：`tool-inventory.md` + `task-decomposition.md`（来自阶段 3+4）
**输出**：`gap-analysis.json`（完备性评估）

---

## 操作步骤

### Step 1：评估理论完整性
基于 `task-decomposition.md` 和理论背景，评估：
- 理论框架是否完整？（complete / partial / missing）
- 是否有理论假设需要验证？

### Step 2：评估工程可行性
基于 `tool-inventory.md`，评估：
- 所有工具是否就绪？
- 数据是否可访问？
- 工程实现是否有障碍？
- 评分：complete / partial / missing

### Step 3：评估工具就绪度
基于 `tool-inventory.md`：
- 工具可用性：complete / partial / missing
- 阻塞项：列出

### Step 4：评估方向正确性
对比 `task-decomposition.md` 和 `acceptance-criteria.md`：
- 当前方案是否能达成验收标准？
- 评分：complete / partial / missing

### Step 5：评估可回滚性
- 每个子任务是否有明确的回滚方案？
- 评分：complete / partial / missing

### Step 6：计算高影响项
列出所有高影响项（如果任何维度为 missing 或 partial）：
```json
{
  "dimension": "维度名称",
  "status": "complete|partial|missing",
  "impact": "high",
  "action": "补救行动"
}
```

### Step 7：写入 gap-analysis.json
输出格式：
```json
{
  "theoretical_integrity": "complete|partial|missing",
  "engineering_feasibility": "complete|partial|missing",
  "tool_readiness": "complete|partial|missing",
  "direction_correctness": "complete|partial|missing",
  "revertibility": "complete|partial|missing",
  "high_impact_items": [
    {"dimension": "", "status": "", "impact": "high", "action": ""}
  ],
  "avg_change_from_prev": "< 20%"
}
```

**必须存在**：`gap-analysis.json`

阶段 3 输出（`task-decomposition.md`）+ 阶段 4 输出（`tool-inventory.md`）
