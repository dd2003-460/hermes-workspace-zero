# 05-完备核验（Stage 5）

**输入**：`tool-inventory.md` + `task-decomposition.md`（来自阶段 3+4）
**输出**：`gap-analysis.json`（完备性评估）

---

## Agent 使用规范

完备核验阶段**必须使用独立 Agent 进行 gap analysis**。Commander 不做自我核验——每个维度的评估必须经过至少一个 Agent 的审查：

| 场景 | 使用 Agent | 原因 |
|------|-----------|------|
| 理论完整性评估 | `general-purpose` Agent（物理领域） | 独立 Agent 发现理论假设中的漏洞 |
| 工程可行性评估 | `general-purpose` Agent | 独立 Agent 发现工程实现中的盲区 |
| 方向正确性评估 | `sub-brain` Agent | 独立 Agent 对比方案与验收标准 |
| 完备性综合审查 | `confidence-judge` Agent | Agent 综合所有维度给出置信度 |

**强制要求**：
- 每个维度的评估必须经过至少一个独立 Agent 的审查
- Commander 不做自证——所有 gap 必须由 Agent 发现
- `avg_change_from_prev` 必须经过 Agent 确认（对比上一轮 gap-analysis.json）

### 🔑 通用核验原则（RED LINES）

**1. 交叉验证 — 多 LLM 独立核验（核心红线）**
- 关键结论必须通过 **至少 2 个不同 LLM 独立审查**，不能仅依赖单一 LLM 的判断
- 如果不同 LLM 给出不同置信度评估，取保守值（较低的那个）

**2. 引用/数据必须实际验证（核心红线）**
- 所有引用和外部数据来源必须**实际访问原链接验证**，不能仅依赖 LLM 的记忆或转述
- arXiv/DOI/URL: 必须打开确认真实存在
- 数值数据: 必须回溯到原始来源

**3. 对"所有检查都通过"保持警惕**
- 当 LLM 报告"无发现问题"时，要求它具体列出检查了哪些项目
- 零错误不等于真的零错误——可能是不充分的检查
- 要求输出详细检查清单，而非简单"通过/不通过"

**4. 置信度评估必须透明**
- 每个置信度数字必须附注计算依据和具体观察
- 不能只给一个最终数字而不展示中间步骤
- 对置信度高的结论，必须能追溯到原始证据

## 操作步骤

### Step 1：评估理论完整性（Agent 审查）
**通过 Agent 执行**：将 `task-decomposition.md` 和理论背景发送给 `general-purpose` Agent，要求审查：
- 理论框架是否完整？（complete / partial / missing）
- 是否有理论假设需要验证？

### Step 2：评估工程可行性（Agent 审查）
**通过 Agent 执行**：将 `tool-inventory.md` 发送给 `general-purpose` Agent，要求审查：
- 所有工具是否就绪？
- 数据是否可访问？
- 工程实现是否有障碍？
- 评分：complete / partial / missing

### Step 3：评估工具就绪度（Agent 确认）
**通过 Agent 确认**：将 `tool-inventory.md` 发送给 `Explore` Agent，确认工具可用性：complete / partial / missing，列出阻塞项。

### Step 4：评估方向正确性（Agent 审查）
**通过 `sub-brain` Agent 执行**：将 `task-decomposition.md` 和 `acceptance-criteria.md` 同时发送给 Agent，要求对比：
- 当前方案是否能达成验收标准？
- 评分：complete / partial / missing

### Step 5：评估可回滚性（Agent 审查）
**通过 Agent 审查**：将 `task-decomposition.md` 中的回滚方案发送给 `general-purpose` Agent，审查每个子任务是否有明确可执行的回滚方案。

### Step 6：计算高影响项（Agent 辅助）
**通过 Agent 列出**所有高影响项（如果任何维度为 missing 或 partial）：
```json
{
  "dimension": "维度名称",
  "status": "complete|partial|missing",
  "impact": "high",
  "action": "补救行动"
}
```

### Step 7：写入 gap-analysis.json（Agent 辅助整理）
**通过 Agent 辅助整理**：汇总所有 Agent 的评估结果，写入 gap-analysis.json。

输出格式：
```json
{
  "theoretical_integrity": "complete|partial|missing",
  "engineering_feasibility": "complete|partial|missing",
  "tool_readiness": "complete|partial|missing",
  "direction_correctness": "complete|partial|missing",
  "revertibility": "complete|partial|missing",
  "high_impact_items": [
    {"dimension": "", "status": "", "impact": "high", "action": ""}
  ],
  "avg_change_from_prev": "< 20%"
}
```
