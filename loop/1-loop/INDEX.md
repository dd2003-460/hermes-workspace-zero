# 1-loop — 信息搜集 + 任务分解（精简版）

> 仅输出 `plan.md` 一个文件。所有阶段的信息都收敛到这一个产物。

## 结构

| 阶段 | 产出 | 说明 |
|------|------|------|
| A. 信息搜集 | （无中间文件） | 收集意图、目标、约束、外部信息、方法路径 |
| B. 任务分解 + Review 策略规划 | `plan.md` | 包含子任务 DAG、每步的 Review 策略、失败修复预案 |

## 不再存在的阶段

- ~~01-任务澄清~~ → 并入信息搜集
- ~~02-目标澄清~~ → 并入信息搜集
- ~~04-信息搜集~~ → 本阶段本身
- ~~05-完备核验~~ → 砍掉 5 维度检查，改为 Review 策略
- ~~06-决策~~ → 合并到 plan.md 的输出判定

## 产出物

只有一个文件：`<project>/plan.md`

```markdown
# plan.md

## 1. 意图
（用户要什么，原始表述 + AI 理解）

## 2. 目标
（可衡量的成功标准，非主观描述）

## 3. 约束
（时间、算力、数据、工具、不可违反的规则）

## 4. 外部信息
（已通过搜索/网页/API 获取的外部数据、文献、参考）

## 5. 方法路径
（采用什么方法、技术路线、工具链）

## 6. 子任务 DAG

### 原子任务定义（何时停止分解）

每个子任务必须是**原子任务**，满足以下全部条件：
1. **单一职责**：只完成一个明确动作（不混合编码+验证+论文写作）
2. **输入输出明确**：输入文件路径 + 输出文件路径均唯一确定
3. **可单次完成**：在单次 per-step 循环中可完成（不跨多次循环）
4. **可独立验证**：有明确的 PASS/FAIL 判定标准

### 多层分解规则

当满足任一条件时，**必须继续分解**，不可停留在当前层级：

| 触发条件 | 动作 |
|----------|------|
| 一个父任务下分出 **>3 个子任务** | 必须分组，每组 ≤3，每组作为一个新层级 |
| 子任务产出不满足原子任务定义 | 继续分解，直到原子 |
| 子任务类型混合（如"写代码+验证+写文档"） | 拆分为纯 code / 纯 verify / 纯 writing |

### 层级编号规则

```
Level 0: 原任务（plan.md 顶层 T1, T2...）
Level 1: T1.1, T1.2, T1.3...  （T1 的直接子任务）
Level 2: T1.1.1, T1.1.2...  （T1.1 的子任务）
Level 3: T1.1.1.1...  （最大深度，此时视为原子）
```

**约束**：
- 最大深度 **3 层**（后缀不超过 3 段）。如果到 Level 3 仍不满足原子任务定义 → 标记 BLOCKED + 原因，不再继续分解。
- 每层的子任务数 **≤ 5**。如果 >3 → 分组（见上表）。
- 每个子任务明确标注其层级：`[L1] T1.1` 或 `[L2] T1.1.1`

### 示例：多层分解

```
T1: 建立模型训练pipeline → 分出 T1.1, T1.2, T1.3, T1.4, T1.5 → >3，必须分解

→ 重组为 L1:
  T1.1: 数据预处理模块（1个任务，原子 ✓）
  T1.2: 模型架构定义模块（1个任务，原子 ✓）
  T1.3: 训练循环模块 → 拆分为 L2:
    T1.3.1: 前向传播实现
    T1.3.2: 梯度计算实现
    T1.3.3: 优化器集成
  T1.4: 验证模块（1个任务，原子 ✓）
  T1.5: 日志记录模块（1个任务，原子 ✓）

最终 L1 有 T1.1, T1.2, T1.3, T1.4, T1.5 = 5个，≤5 ✓
T1.3 有 T1.3.1, T1.3.2, T1.3.3 = 3个，≤3 ✓
```

每个子任务定义为：
- **ID**: T1
- **描述**: （做什么）
- **类型**: [code | paper | data_prediction | research | other]
- **输入**: （前置子任务的输出文件路径）
- **输出**: （本任务产出文件路径）
- **Review 策略**: （见下方 Review 策略定义）
- **依赖**: [T0] （仅列出直接前置任务 ID）
- **并行允许**: [true/false]
- **失败修复预案**: （如果 Review 不通过，怎么分解修复子任务）

## 7. Review 策略定义

| 任务类型 | 验证方式 | 交叉验证 |
|----------|----------|----------|
| code | 直接运行测试/单元测试/功能验证 | 网页 LLM review 代码逻辑 |
| paper/writing | 传文件给网页 LLM 评审 | 人工审阅关键论点 |
| data_prediction | 用实际数据验证预测结果 | 网页 LLM 评估方法论合理性 |
| research | 结论与外部信息交叉验证 | 网页 LLM 评估逻辑完整性 |
| other | 根据任务性质定义特定验证方式 | 网页 LLM 交叉确认 |

**所有 Review 必须通过网页 LLM 交叉验证**（除纯代码测试外）。
```
