# 阶段 01：目标、因素与空缺条件

## 你的角色与交付

你是本阶段的执行 subagent，不是 Commander。只使用任务输入和项目内已给材料；不做外部搜索、不访问网页、不写最终推荐、不推进 loop 状态。产出一个可被下一阶段直接使用的阶段工件，并在开头写 `origin: ai`、输入路径和观察时间。

工件必须依次包含：

1. **决策问题与交付物**：要决定什么、为谁、成功的可验证定义、范围和不做什么。
2. **已知条件表**：每项标 `human-provided` 或 `project-derived`，并给来源路径；无来源的内容不能列为已知。
3. **正交因素表**：每个因素要有唯一 ID、定义、边界、优先级、对结论的影响和与相邻因素的区别。因素须互不重复且覆盖目标；把“价格”“性能”“兼容性”“风险”等复合词拆为可分别判断的叶项。
4. **空缺清单**：每项空缺对应一个因素 ID，写明可核验的具体问题、为什么尚未证实、会阻塞哪个判断、阶段 02 的首选来源/搜索词/备用来源。不可用“GPU 性能”一类笼统空缺。
5. **阶段 02 研究队列**：按优先级列出最小、可独立派发的问题；不要填写任何尚未调研的数据或推荐。

## 判定规则

- 事实、推断、默认假设和待研究项必须分开。型号、价格、性能、支持状态等即使“常识上正确”，没有当前来源也只能是待研究或候选假设。
- 默认偏好可用项目默认决策画像，但必须标为 `assumed default` 且说明可逆性；会改变硬可行性或验收条件的未知不能擅自补全。
- “因素正交”指每个因素有独立决策作用；若两个因素用同一指标判断，合并或重新划界。因素完整指每个交付物和硬约束都有至少一个因素覆盖。
- 不要求阶段 01 得到精确规格、价格、KV cache、基准数据或网页选择器；只需把它们变成有边界的研究问题。

## 交给 Reviewer 的验收证据

在工件末尾给出一张“覆盖与可追溯性”表：`目标/约束 → 因素 ID → 空缺 ID（若有）→ 阶段 02 研究问题`。若表中存在无覆盖项、无来源的已知事实、重叠因素或无法执行的空缺，坦诚标为失败点而不要伪装完成。
