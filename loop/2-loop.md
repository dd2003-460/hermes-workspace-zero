# 2-loop — Execution（全局执行流程）

**原则**：严格按工程顺序完成原子执行，通过验证门禁。不是"完成任务"，而是"做正确的事+验证做得正确"。

## 流程
```
pre-check → backup → execute → verify → confidence → decision
```

## 1. 预检查
- 任务包存在
- 阶段允许执行
- 核心文件和模块存在
- `owner_project`、`working_paths`、`expected_outputs`、`rollback_target` 明确
- 修改位置符合项目规范

## 2. 备份
修改前必须备份：`cp <file> backups/YYYY-MM-DD/<file>.bak`
批量修改时每个文件单独备份，`diff` 验证完整性。

## 3. 执行
- 真正做事：写文件、搜索、分析、更新索引
- 不得只写模板然后标完成
- 新脚本/目录落在规范位置
- 新入口/脚本必须更新索引

## 4. 验证（4 步核验，不可跳过）
1. **还原要求** → 列出每个可验证交付物
2. **逐一核验** → 有产出？存在且完整。无产出？标记未完成
3. **质量自检** → 有实质内容、服务目标、无禁止动作
4. **置信度** → 评分工具必须调用

## 5. 置信度门槛
| 评分 | 判定 | 动作 |
|------|------|------|
| < 0.6 | 低 | 不得 completed。标注不确定，生成遗留分支 |
| 0.6-0.8 | 中 | 标注不确定，记录未验证假设 |
| > 0.8 | 高 | 正常通过 |

## 6. 分叉决策
- **completed** — 全部通过 + 置信度 > 0.6 → 标记完成，生成下一步
- **completed_with_branches** — 置信度 0.3-0.6 → 标记完成，生成遗留分支
- **needs_replan** — 置信度 < 0.3 或任何核验未通过 → 回滚，回 1-loop

## 环节标注
输出开头声明：`[环节: create]` / `[search]` / `[analyze]` / `[verify]` / `[report]`
不得跳过 verify 到 report。

## 测试规则
- 脚本/工具必须运行至少一次测试
- 测试失败 → 默认回滚，不得偷偷小修继续跑
- 纯文档可豁免

## 目录规范
- 项目数据放 `projects/<owner>/data/`，不放根 data/
- 根 scripts/ 只放共享脚本

## 公共规则
- agents + 步骤确认
- 按索引读
- 状态读写显式
- 单任务路径
- 结果和证据优先
