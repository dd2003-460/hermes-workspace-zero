# DNS 诊断与网络绕过方案（iteration 24-25）

## 关键发现

### 网络状态
- **ICMP（ping）**: 完全正常（ping 8.8.8.8 延迟 0.267ms）
- **DNS**: 完全阻断（nslookup 全部超时，dig 全部超时）
- **HTTP/HTTPS**: 表面阻断，实际是 DNS 问题
  - `curl`（无 --resolve）: HTTP 000（因为 DNS 解析失败）
  - `curl --resolve <host>:443:<ip>`: 完全可用

## 绕过 DNS 的方法
```bash
# 1. curl --resolve（已验证）
curl --resolve "github.com:443:20.205.243.166" https://github.com/...

# 2. 修改 /etc/hosts
echo "20.205.243.166 github.com" | sudo tee -a /etc/hosts
echo "131.188.12.211 ftp.fau.de" | sudo tee -a /etc/hosts
echo "151.101.64.223 pypi.org" | sudo tee -a /etc/hosts

# 3. 修改 DNS 服务器（需要 sudo）
networksetup -setdnsservers Wi-Fi 8.8.8.8
```

## 结论

**根本问题不是网络被阻断，而是 DNS 被阻断。** `curl --resolve` 可以绕过 DNS 直接访问远程主机。这解释了为什么之前所有 HTTP 测试都失败（DNS 解析失败导致连接超时），但 ping 可以工作。

修复 DNS 是最小改动最大收益的方案。
