# 第 5 轮 Goal 落盘 · 打分器信度 + n≥5 权重复校 + token 测量边界 + 终态效度

> origin: ai · 2026-10-25 · 承接 goal-9c250b87（第 4 轮 · bench.md r4 已知缺陷 6 条）
> 创建方式：subagent 无 create_goal 权限 → 本文件落盘 + 报 Lead（链路第 0 步硬规则）

## Goal（一句话）
把 r4 暴露的「分是过程纪律审计分、不是能力分」问题往下推一层：打分器之间要有信度（双打分器 κ），权重要在 n≥5 上重校，token 测量的边界要说清楚，并第一次用终态效度任务检验过程分是否预测任务成败。

## 背景（r4 遗留 · bench.md r4 已知缺陷 6 条）
1. n=3 相关矩阵退化：goal 公式下 6 指标全部 max|r|>0.7，权重实质未变（相对权重几乎不变）→ 权重校准需在 n≥5 上做
2. M4「独立源」无操作化定义：自估把执行锚点/上轮回执/单通道 web_search 过度计入，被独立裁决打回 86.7→50.0
3. 独立打分器仅 1 个（DeepSeek）→ 打分器之间的信度未知（R2 建议 Fleiss'κ）
4. output token / 压缩净省不可测：bili.log 无 per-request output 行，压缩无「不压缩」反事实基线
5. run2 arena 侧 token unverified（外部无账本；仅规则负载 12,086 o200k/会话每轮重发=实测）
6. bench 分=过程纪律审计分非通用能力分 → 需要终态效度检验（过程分是否预测任务客观成败）

## 验收（全部可机器验证，n=1 判 fail 不降级）
1. **双打分器信度**：新增第二个独立打分器（通道必须不同于 DeepSeek，如 ego-browser ChatGPT 或其他已登录网页 LLM），对 r4 已有 3 个 run + 本轮新增 run 的 M1-M6 重打；报告两打分器逐指标分差 |Δ|、一致率（|Δ|≤15 占比）+ 可算的 κ（n 足够时 Fleiss'/加权 Cohen's κ，n 不足则如实标注不可算）；|Δ|>15 的项按 r4 裁决规则（哪边对+锚点）定终版分
2. **n≥5 权重复校**：新增 ≥2 个 run（通道必须与既有 3 run 不同或互补：arena / subagent / 本地 Lead 中至少补 2 种），每个 run 走完整 9 步链路并挂 M7 锚点；n≥5 重算 M1-M6 相关矩阵，|r|>0.7 指标按 原权重×(1-|r|/2) 调权并归一化，推导写入 bench.md；若仍退化（全指标 max|r|>0.7），如实标注并给出自推导的非退化调权公式
3. **token 测量边界**：① 查 bili 侧 per-request output token 字段是否存在（/__bili/stats、/__bili/logs、源码或 issue 任一通道；查不到则写明查过的端点/文件 + URL + unverified）；② run2 arena 侧 token：能取到 arena 会话回执就实测入账，取不到维持 unverified + URL；③ 给出「本 bench 当前可测/不可测 token 维度」清单（input 可测 / output 不可测 / 压缩净省不可测 / cache 命中率 provider 未上报）
4. **终态效度首测**：设计 ≥1 个终态效度任务（任务成败由客观终态判定，如：生成物可运行/可解析/可复现，与过程锚点无关），用同一链路跑 1 次，记录「过程分 vs 终态成败」对照；若终态失败而过程分高，如实记录并分析哪个指标失效
5. **bench.md r5 落盘 + push pfb + ls-remote 验证 + 第 6 轮 goal 落盘**（第 6 轮候选：多任务类型扩展 bench 边界 / 权重敏感性分析 / cache 命中率 provider 侧补报 / bench 与开源 agent 系统同任务对比协议）
