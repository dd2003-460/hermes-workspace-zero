## 已知缺陷（进 R5）

1. n=3 相关/调权退化——需 n≥5 run 才能有效校准权重
2. M4「独立源」口径仍依赖裁决者主观——需操作化定义（如：不同 provider 且不同 prompt 模板的回执对）
3. output token 与压缩净省不可测（bili 账本字段缺失）——需 provider 侧 cache 上报或换账本口径
4. run2 arena 侧 token 总量 unverified（外部系统无账本）
5. 独立打分器仍只 1 个（DeepSeek）——R5 加第二独立打分器做打分器间一致性（Fleiss'κ，R2 建议）
6. 权重向量实质未变（退化的副产品）——bench 分数目前=「过程纪律审计分」，不是通用 agent 能力分

### Fleiss κ = 0.258（低一致下沿）

- 24 项（run1-3 × M1-M6 两方盲打 + run4 M1-M6 lead vs chatgpt），5 档 bucket 化
- P_observed 0.583 vs P_expected 0.438
- **根因判定：证据包版本不对称**。DeepSeek(r4) 的证据包缺任务书行数/轮数字段（其 key_reasons 自述"无法判断 ≤200"），ChatGPT(r5.1) 拿到补齐版 prompt → M2 Δ25、M5 Δ20 是信息不对称不是判断分歧。剔除 M2/M5 后剩余 4 指标 16 项分歧集中在 M1 ±15 档内。

### 结果（新权重）

- **n=5 mean±std = 78.91±13.15**（9 scorer-totals）
- 排名：run4(97.63) > run5(84.93) ≈ run3(84.90) ≈ run1(83.29) > run2(63.16)
- 第二梯队三者差距 <2 点，统计上不可区分
- run2 垫底且与本地通道差 ~21 点：**差距主要在 M1（重发放大 25 vs 78-95）而非断点纪律（M3 仅差 20 点）**——arena 通道的 token 效率问题是结构性（规则每轮全量重发），不是执行质量问题
- per-metric consensus：M1 62.6 / M2 88.9 / M3 91.1 / M4 56.1 / M5 91.1 / M6 95.0 —— **M4 交叉验证是当前最弱维度**（均值仅 56.1），与外部 baseline 结论呼应：过程纪律审计里"独立源"是最难做到的

### Caveats

1. κ 用 5 档 bucket 化有粒度损失；原始 Δ 分布见回执
2. run5 只有 Lead 单评分（派发时未含在证据包）——独立性打折，r6 补盲打
3. Pearson n=9 置信区间仍宽，新权重为方向性校准，r6 复算确认稳定性
