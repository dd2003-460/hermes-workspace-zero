# M8 提案：首次通过率（first-pass rate）

## 定义

对一次 run **在执行前冻结**的交付物验证点集合 \(V\)，定义：

\[
M8 = 100\times\frac{\#\{v\in V: v\text{ 在第一次验证时通过，且此前未因该验证点修改交付物后重跑}\}}{|V|}
\]

分数范围 0–100。每个验证点是一个原子、可重复判定的验收断言（有明确 oracle/命令/预期结果），同一断点不得拆成重复断言来放大分母或分子。

### 计分规则
1. 验证点清单、粒度、验证器与分母必须在首次执行前冻结并留痕。
2. 只看该点第一次执行的结果；首次失败后修改交付物再通过，M8 仍记 0，另报最终通过率。
3. 未执行/环境阻塞的点留在冻结分母，M8 不计通过，并单独标 `blocked/not-run`，不伪装为失败的根因分类。
4. 环境瞬断、命令失败、内容错误分别记录；只有首次验证确实返回通过才记 1。重跑不覆写首轮记录。
5. 同时报 `first-pass numerator/denominator`、每点首轮结果、修改/重跑次数、最终状态；仅报百分比不够可审计。

## M8–M3：共线风险与权重决策

| 项 | M3 断点通过率 | M8 首次通过率 |
|---|---|---|
| 粒度 | 链路级 A/B/C 断点及 gate（仓库 `bench/self-opt-tester/bench.md` 定义） | 交付物级、预注册原子验证点 |
| 时间口径 | 断点/gate 最终是否通过 | 第一次验证结果；修复重跑不回填 |
| 可能重叠 | 仓库可达、任务书完整、产出可 push 等步骤也可能是交付检查 | 若把同一 gate 再列成 validation point，会重复计量 |
| 不同信息 | 链路能否走通/交接 | 产出初始质量与返工需求 |

**当前 M8 自评：100/100 = 10/10 个本提案交付验收点首轮通过。** 此数值只描述本次 `m8-proposal.md`/回执的首轮内容审计，不是跨 run 均值、不是外部评分，也不证明 M8 的构念效度。以下 10 项在首轮审计前冻结；审计结果和定位一并留痕：

| # | 交付物验证点 | 首轮结果 | 定位 |
|---:|---|---|---|
| 1 | 分子、分母、0–100 公式明确 | 通过 | 本节“定义”公式 |
| 2 | 验证点原子性与执行前冻结分母 | 通过 | 计分规则 1 |
| 3 | 首次失败后修复重跑不回填 | 通过 | 计分规则 2 |
| 4 | 未执行/阻塞点分母处理明确 | 通过 | 计分规则 3 |
| 5 | 首轮结果与最终通过率分开报 | 通过 | 计分规则 5 |
| 6 | M3 定义与 M8 区别明确 | 通过 | M8–M3 对照表 |
| 7 | 当前 r 无法估计，未伪造系数 | 通过 | “相关系数与权重” |
| 8 | `|r|>0.7` 规则与待采样决策写明 | 通过 | “相关系数与权重” |
| 9 | 两个独立来源及其局限/观察时间写全 | 通过 | “外部先例核验” |
| 10 | 精确 M8 先例缺失标 `unverified` | 通过 | 外部核验结论 |

首次审计时 10 项均齐全；若此后修改上述内容，不得倒算成“首轮通过”。

### 相关系数与权重
- 当前 **r(M8,M3) 不可估**：历史 bench 只有 M1–M6；本轮仅一个 M3/M8 配对（n=1），Pearson r 无定义。不得把同一 run 的两个分数相等说成 r=1。
- 既有先验证据提示过程指标共线：r4 n=3 中 M3–M4=0.9982、M3–M6=0.9425、M2–M3=0.7608；但这不是 M8 的相关数据，且 n=3 很不稳定。
- **建议：当前不把 M8 并入综合权重，先作为 shadow metric 单列报告。** 累积至少 5 个独立 run 的配对 M3/M8 后（n≥5 仍属探索性），按 Pearson `|r|>0.7` 规则评估；若越阈值，依本仓已有校准式对高度相关指标折权并归一化，同时给出 n/置信区间/敏感性。若未越阈值，也需检查不同验证点粒度编码下结果是否稳定。

## 外部先例核验

1. **OpenAI HumanEval**：<https://github.com/openai/human-eval/blob/master/README.md>。README 展示 `pass@1`，保存 completion、执行测试并输出每条 completion 的 passed/failed。页面当前标记 deprecated/unmaintained；最新 README commit 页面显示 2026-10-16，本次观察 2026-10-29。它支持“一个样本通过测试”的邻近构念，但分母是 completion 样本，不是同一交付物的验证点，也没有 M8 的修改后重跑规则。
2. **Sierra Research τ-bench**：<https://github.com/sierra-research/tau-bench/blob/main/README.md> 与 <https://github.com/sierra-research/tau-bench/blob/main/tau_bench/run.py>。README 报告工具型 agent 的 Pass^1…Pass^4；实现按 task 汇总多个 trial 的 reward，Pass^k 以组合数估计，k=1 对应单 trial 成功率。README 当前提示旧 task 已过时并推荐 τ³-bench；页面显示 README commit 2026-03-18，本次观察 2026-10-29。它是 agent benchmark 的直接邻近例，但单 trial 不是“验证点首次通过且无改件重跑”。

**交叉核验结论：M8 精确到“交付验证点 + 未修改重跑”的既有 agent-eval 标准定义未找到，标记 `unverified`；上面两项只能作为相邻 pass@1/pass^1 先例，不能宣称定义已被外部验证。**

## 局限与实施建议
- M8 对验证点粒度敏感；用例越碎，分数越容易被操纵。应固定验收点模板、哈希冻结验证集、记录首轮日志。
- M3 与 M8 可能受共同的任务难度/交付质量影响；单 run 不能做相关判断，且高相关不代表其中一个无效。
- 下一轮先影子记录 M8 的分子/分母和逐点首轮日志；收集配对 runs 后再调权，避免先赋权再找证据。
