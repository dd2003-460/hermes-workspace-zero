**B 臂副作用（新发现，n=10 才暴露）**：提醒词让模型过度保守——Q09 B 臂 c4 从 10/10 掉到 1/10。机制：B 臂输出 435 字符（声明"无法确定唯一答案"即停），A 臂 1707-1848 字符（声明缺口**同时**算了可算的部分量 bytes/step=33 GB）。提醒词只说"缺参数就声明无法确定"，没说"能算的部分量仍要算"→ 模型把"无法确定"理解成整体放弃。**这是真实的 tradeoff：缺口报告/防编造收益（c1 +20/30, c3 +5/30）vs 部分计算损失（c4 −9/30，集中在 Q09）**。修复方向：提醒词加一句"对题面已给参数可独立计算的部分量，仍应给出数值"。

**B' 臂（加部分量修复句，n=10 完成，11-23）**：Q09 冒烟 c1/c3/c4 全 True（975 字符，明确算了 33 GB/token）→ c4 副作用修复有效。**全量确认**：Q09 B' c4 10/10（B 臂 1/10，修复有效）；Q10 B' 全 10/10。**Q08 c3 灰区 n=10 确认**：strict 3/10 → **lenient（假设性提及豁免）10/10**——7 个 strict FAIL 全是"虽然 H100 SXM 通常配备 80 GB…无法确定是否 fit"式假设性提及（句内含 若/如/通常/typical），lenient 全豁免。Q09/Q10 两口径一致 10/10。**结论：B' 行为在认识论上最优（命名可能值 + 明确不采纳 + 计算可算部分），strict c3 掉分是纯判分 artifact 非模型退步**。出处：scripts/rd_ab_bprime_n10.py + /tmp/rd_ab_bprime_n10.json（30 run）+ scripts/c3_lenient_rejudge.py（双口径重判）。

## 核心实验正式跑：prompt 变体敏感性（n≥100，2026-11-23 进行中）

pilot（judge-boundary-findings §4）只有 n=24，CI 太宽。正式跑：67 真实输出 × 3 prompt 变体（V1_strict/V2_loose/V3_engineer）= 201 次 LLM judge 调用（scripts/prompt_variant_formal.py）。

**【D 2026-11-23 指出长度混淆 → 已量化确认】** 汇总格式失败率是 67 个长度 385–7210 字符输出的堆叠，若长输出更易让 judge 吐不可解析 JSON，则失败率含"长度驱动"成分，直接报"prompt 驱动格式不可靠"会过度归因。分离方法：同输出跨 3 变体比较（长度固定=纯 prompt 效应）vs 跨输出长度分桶（长度效应）。

**V1_strict 全 67 次（已完成）长度混淆信号**：
- 失败率随长度单调升：Q1（385–687 字符）30.8% → Q2（687–961）92.3% → Q3–Q5 稳定 85–92%
- 失败 case 平均长度 1368 vs 通过 case 782
- **700 字符处是台阶非渐变**（30.8% 直跳 92.3%）→ 不像"注意力稀释"平滑效应，更像推理链撞 max_tokens=500 截断的阈值效应

**V1 vs V2 重叠 44 输出（长度固定，纯 prompt 效应）**：
- 32/44 全挂（两变体都不可解析）= 73% → 输出/长度驱动
- 5/44 混合（同输出 V1 挂 V2 过或反之）= 11.4% → 纯 prompt 效应
- **结论：prompt 措辞只解释 1/9 失败，输出长度解释 8/9**

**机制判别（截断 vs 指令遵循，探针 6/6 完成）**：对 V1 失败 case 用 max_tokens 500→2000 重判（scripts/mt_truncation_probe.py）。
- Q01(2280)/Q02(1492)/Q04(2646)/Q05(7210)/Q06(1328)：mt500=False → mt2000=**True**，raw_len=74/74/62/78/63（纯 JSON 无推理链）→ **截断驱动**（mt500 把推理路径截断，给够空间模型就只输出 JSON）
- Q03(1720)：mt500=False → mt2000=**False**，raw_len=3190（给够 2000 token 仍输出长推理链不肯只给 JSON）→ **指令遵循例外**
- **恢复率 5/6 = 83% 截断驱动，1/6 = 17% 指令遵循**
- **直接证据（finish_reason）**：6 个 mt500 失败 case 全部 `finish_reason=length`、`completion_tokens=500`（vLLM 明确报告输出撞 max_tokens 上限被截断）——截断不是推断，是引擎直接报告。Q03 例外是 mt2000 下模型仍输出 3190 字符推理链（finish_reason=stop 但 JSON 缺失）= 指令遵循问题，与截断独立。
- **台阶精确定位 604 字符**：按长度排序，604 字符前 10 个失败 1/10=10%，之后 57 个失败 51/57=89.5%——604 字符 ≈ 推理链撞 500 token 阈值
- **结论：格式失败 = max_tokens 截断（主，83%）+ 指令遵循（次，17%）的交互，两者都随输出长度上升**。纯"注意力稀释"假设被台阶形态否定（稀释应平滑，这里是阈值跳变）。

**对论文 claim 的影响**：格式可靠性失败主驱动 = 输出长度 × max_tokens 截断交互（73% 输出驱动），prompt 措辞次要（11%）。比"prompt 驱动格式不可靠"更准且更可操作——缓解 = 提 max_tokens + 强制 JSON-only 解码，比"换机械 judge"更具体。机械 judge 优势细化为"格式 100% vs 受 max_tokens 截断约束的 ~30–90%（随输出长度）"。
