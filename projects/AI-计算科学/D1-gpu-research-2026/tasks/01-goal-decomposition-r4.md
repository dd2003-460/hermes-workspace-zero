# 阶段 01 r4 工件：结构化递归分解（按任务自身词 → 正交 → 递归 → 原子）

## 0. 本 r4 为何（修复 r1-r3 扁平枚举）
r1-r3 把因素写成扁平并列(F1-F16 平并列)。错: 缺第1层正交拆、层级混、非正交、未递归到原子。r4 按正案例: 先拆任务自身词, 每层拆"一个"因素正交+完整, 递归到原子。

## 1. 目标与交付物
- 目标(任务自身词): 性价比最高的 27B 模型 运行的 硬件系统。
- 交付物: 推荐硬件系统(候选+排序+适用边界), 在"性价比"=性能/成本 准则下, 满足"运行 27B 模型"硬约束。

## 2. 第1层 — 拆任务自身词(正交+完整)
"性价比" 由两个正交因素决定(合完全定义性价比):
- F1 性能 — 该硬件运行 27B 模型"如何"
- F2 成本 — 该硬件"花费"多少
- 正交: 性能不含成本、成本不含性能; 合: 性价比=F1/F2 完全由二者。
- 硬约束(横层): 27B 模型需显存 ≥ 27B×bytes/param → 候选集合门(G1 决定 bytes/param)。

## 3. 第2层 — 递归 F1、F2
- F1 性能 = F1.1 速度 × F1.2 质量(正交: 速度=吞吐/延迟, 质量=输出正确/能力; 合完全定义"运行如何")。
- F2 成本 = F2.1 硬件成本 + F2.2 运行成本(正交: CAPEX vs OPEX; 合完全定义"花费")。

## 4. 第3层 — 递归 F1.1/F1.2/F2.1/F2.2
- F1.1 速度 = F1.1.1 prefill 速度 × F1.1.2 decode 速度(正交: 两推理阶段; 合完全定义速度)。
  - F1.1.1 prefill 速度 ← 算力(compute-bound) → 原子(受 TFLOPS/算力)。
  - F1.1.2 decode 速度 ← 显存带宽(memory-bandwidth-bound) → 原子(受 HBM/带宽)。
- F1.2 质量 = F1.2.1 精度 × F1.2.2 上下文能力(正交: 数值精度 vs 长上下文; 合完全定义质量)。
  - F1.2.1 精度 → 原子(受量化 FP16/INT8/INT4)。
  - F1.2.2 上下文能力 → 原子(受 KV cache/显存)。
- F2.1 硬件成本 = F2.1.1 单卡价格 × F2.1.2 卡数(正交: 单价 vs 数量; 合完全定义硬件成本)。
  - F2.1.1 单卡价格 → 原子(待 02 一手)。
  - F2.1.2 卡数 → 原子(受显存需求/并行)。
- F2.2 运行成本 = F2.2.1 功耗 + F2.2.2 散热 + F2.2.3 维护(正交; 合完全定义 OPEX)。
  - 各 → 原子。

## 5. 停止判定(原子)
叶子原子: {算力, 显存带宽, 精度, 上下文能力, 单卡价格, 卡数, 功耗, 散热, 维护}。所有非原子(F1,F2,F1.1,F1.2,F2.1,F2.2)已递归展开 → 分解完成。层级嵌套清晰(父含子, 不并列)。

## 6. 条件分类(H/D/R/G)
- H(人类已给): 27B 模型规模; 性价比准则(性能/成本); 交付=硬件系统。
- D(项目可推导): 显存需求=27B×bytes/param(once G1 known); 候选硬件集合(r1-r3 已一手✓ 规格); 性价比排序公式。
- R(仍需研究, 属 02): 各候选单卡价格(F2.1.1); 各候选 prefill/decode 实测吞吐(F1.1); 量化质量门槛(F1.2.1); 功耗/散热实测(F2.2)。
- G(空缺需用户决策, 未给): G1 精度/量化偏好; G2 预算上限; G3 部署形态(单/多卡/桌面/服务器); G4 并发/SLO; G5 采购时点; G6 上下文长度需求。

## 7. 空缺清单(结构化, 挂于因素, 不扁平)

- G3 部署形态 → 挂 F2.1.2 卡数 + 候选集合 → 阻塞: 候选集合 + 成本。
