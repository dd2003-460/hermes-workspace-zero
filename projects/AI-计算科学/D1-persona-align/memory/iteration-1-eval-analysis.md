# Iteration 1: Eval 结果偏差分析

**日期**: 2026-05-21
**作者**: AI (Ralph Loop Iteration 1)
**类型**: 核验

## 核心发现

### method_only 的 system prompt 只有 80 个字符

```
你是一个研究者。分析问题时必须：1) 识别问题的所有关键变量 2) 区分相关和因果 3) 考虑可能的混淆因素 4) 明确你的结论在什么条件下成立。用中文。
```

而 chenglu_persona 有 ~200 个字符，包含 6 条具体的思维特征。

**关键问题**: 方法提示越简洁，效果越好。因为简洁的方法提示告诉模型"你自己想"，而 persona 提示告诉模型"你应该是这样的"。前者释放模型能力，后者限制模型能力。

### 评分机制偏差分析

`score_response()` 的关键维度：
1. **length_reasonable**: < 300字 = 0分, >= 300字 = 1分
2. **depth** (权重 1.5): 关键词密度 / 3, 上限 1.0
3. **block_structure** (权重 1.0): 是否有结构化标记
4. **uncertainty** (权重 1.0): 是否有不确定性标记
5. **question_ratio** (权重 1.0): 反问/追问数量
6. **cross_domain** (权重 0.8): 跨领域词汇数量

**最大偏差源**: `length_reasonable` 是一个硬门槛（300字），但 method_only 在 unified_language 上只给了 338 字却还能得分，而 persona 在 agent_capability_test 上只有 287 字直接扣 0.5 分。

**结论**: 评分机制对"深度分析"有系统性偏好（depth 权重最高 1.5，结构化标记要求），这恰恰是 method_only 擅长而 persona 不保证的。

### 修正后的理解

原结论"method_only > persona"仍然成立，但理由需要修正：

1. **不是"方法 > 身份"**，而是**"分析方法 > 身份描述"**
   - method_only 给的是**分析框架**（变量识别、因果区分、混淆因素），这些直接指导模型输出高质量分析
   - chenglu_persona 给的是**身份描述**（你是这样的人、你有这些思维方式），但这些描述过于抽象，模型不知道"贝叶斯思维"具体意味着回答格式

2. **persona 的失败原因**: 没有指定**回答结构**。告诉模型"你是贝叶斯思维"不等于告诉模型"你的回答应该包含先验、似然、后验的推导过程"。

3. **LoRA 的失败原因推测**: 68 个 persona 样本可能都是"结论性回答"而非"分析过程"，导致微调过拟合了输出格式。

## 修正后的方向

**思维引擎架构 v2**:
- **方法层（高权重）**: 收到问题后，先确定问题类型（因果推断？还原论？元认知？），然后调用对应的分析框架
- **结构层（强制）**: 输出必须包含：①问题拆解 ②关键变量 ③替代假设 ④边界条件 ⑤不确定度标注
- **身份层（低权重）**: 只在最后标注"成璐风格"——简洁直接、中文优先，不做过度展开
