## Phase 1: 问题澄清

### 真正的问题

"Agent 究竟需要什么性能？" 这个问题需要分解：

1. **Agent 的定义**: 通过迭代规划、工具使用、推理来解决复杂任务的 LLM 系统
2. **性能维度**: 推理能力、规划能力、工具使用、记忆/状态跟踪、多步协作
3. **性能指标**: 成功率、工具调用准确率、规划一致性、幻觉率

### 验收标准

- "性能足够" = 能完成用户复杂任务（如 Ralph Loop 的多阶段自主执行）
- 关键指标: 任务成功率、多步一致性、工具使用准确率

## Phase 2: 分层分析

### 2.1 分层能力模型

**Ritchie et al. (arXiv:2601.09032)** 建立了 empirically derived 的 agent 能力层次：

```
Tier 5: Common-sense reasoning (最基础)
Tier 4: Groundedness (与现实世界对齐)
Tier 3: Adaptability (适应新情况)
Tier 2: Planning (多步规划)
Tier 1: Tool use (最基础)
```

**关键发现**: 弱模型连基础层都做不到，强模型在 contextual inference 上仍有困难。

### 2.2 Layer-wise 动态

**Cui & Luo (arXiv:2605.27935)** 发现：

- Agent 推理 "progressively recruits deeper layers to stabilize outputs and correct errors over long trajectories"
- 深层网络负责状态跟踪和错误纠正
- 多轮 planning 需要更深的网络参与

** implication**: Agent 需要至少 70B 参数的模型才能有稳定的多轮推理。7B-13B 模型在长轨迹中能力退化明显。

### 2.3 性能瓶颈

**CocoaBench (arXiv:2604.11201)** 评估统一数字 agent:

- "Considerable room for improvement in reasoning and planning"
- Tool use and execution: 差距最大
- Visual grounding: 也是瓶颈

**关键洞察**: Agent 的核心瓶颈不是"单个步骤的推理"，而是"多步一致性"。

### 2.4 工具使用性能

**PhysicianBench (arXiv:2605.02240)**:

- 平均 27 次工具调用/任务
- 需要跨多个 encounter 检索数据
- 需要 verifiable execution

**Hierarchical Planning (arXiv:2512.11143)**:

- LLM agents "struggle with maintaining coherent long-horizon plans"
- 混合 classical planning 可改善

### 2.5 记忆与状态跟踪

**PAACE (arXiv:2512.16970)**:

- 优化 agent 状态管理
- 减少 context load 同时提高正确性

**Youtu-LLM (arXiv:2512.24618)**:

- "Long-context reasoning and state tracking within a minimal memory footprint"
- 结构化 curriculum 训练

## Phase 3: 边界检查

### 关键结论的边界条件

1. **"70B+ 是 agent 的门槛"** 成立条件:
   - 复杂多步任务 (>5 steps)
   - 需要工具使用和规划
   - 长轨迹 (>10 turns)

2. **"工具使用是最大瓶颈"** 成立条件:
   - 真实环境 (不是 benchmark)
   - 需要 verifiable execution
   - 多工具协同

### 替代解释

1. **模型大小不是唯一因素**: 微调/训练方式对 agent 能力的影响可能比模型大小更大。
   - Youtu-LLM 证明小模型也可以通过 curriculum 训练获得 agent 能力
   
2. **架构设计可能比模型大小更重要**: Hierarchical Planning (2512.11143) 显示 classical planning 可弥补 LLM 的规划缺陷。

## Phase 4: 数据搜集

### 关键发现

从 14 篇论文 (2024-2026) 汇总:

| 能力维度 | 当前 SOTA 表现 | 差距 |
|---------|---------------|------|
| Tool use | 60-70% 单次调用准确 | 多工具协同 < 40% |
| Planning | 50-60% 长轨迹一致性 | 20+ turns 后显著下降 |
| Reasoning | 70-80% 单步推理 | 多步推理 < 50% |
| Adaptability | 50-60% 新场景 | 需要 online learning |
| Groundedness | 60-70% 现实对齐 | 幻觉问题持续 |

### 硬件需求推断

基于上述性能数据：

- 要稳定在 70%+ agent performance: 需要 70B+ 模型
- 要支持长轨迹 (20+ turns): 需要 100K+ context
- 因此需要: 70B 模型 + 100K context → HBM GPU (A100/H100) 或 Apple M4 Max (184GB)

## Phase 5: 综合结论

### 对成璐的 Ralph Loop 场景

成璐的 agent 系统 (Ralph Loop) 需要:

1. **推理能力**: 多层自我质询 → 需要深层网络 (70B+)
2. **规划能力**: 1-loop/2-loop 多阶段 → 需要长轨迹一致性
3. **工具使用**: 文件操作、代码执行、web 搜索 → 需要 27+ 次工具调用能力
4. **记忆**: 长对话历史 + 研究报告 → 需要 100K+ context
5. **多 agent 协作**: 多个 agent 同时执行 → 需要高并发推理

### 硬件建议

| 场景 | 推荐 | 理由 |
|------|------|------|
| 本地 agent | Apple M4 Max 184GB | 统一内存可容纳 70B 4-bit 模型 |
| 云端 agent | NVIDIA H100 (80GB) | vLLM + PagedAttention 最佳生态 |
| 混合方案 | 本地 M4 Max + 云端 H100 按需 | 性价比最优 |

### 不确定性与后续

1. **小模型 agent**: Youtu-LLM 证明 7B 模型通过 curriculum 可获得 agent 能力。需要进一步研究。
2. **混合架构**: Classical planning + LLM 可能比纯 LLM agent 更高效 (Hierarchical Planning)。
3. **Agent 能力层次**: Ritchie et al. 的层次是否适用于所有场景？需要验证。
