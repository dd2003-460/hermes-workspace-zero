# 思维引擎 v2 — Prompt 设计方案

**日期**: 2026-05-22
**版本**: v2
**基于**: Iteration 1 分析 + Iteration 2 初步 eval 结果

## v1 问题分析

thinking_engine_v1 的 prompt 有 ~900 字符，问题：
1. **说明过长**: 每个阶段都有大量解释性文字（"列出影响这个问题的所有关键变量。区分内生变量/外生变量/混淆变量"）
2. **与 max_tokens 竞争**: 900 字符的 prompt 占用 token budget
3. **5 个阶段全输出 vs 只内化**: v1 要求模型"按顺序输出每个阶段"，导致大量元注释（"### 第一阶段：问题拆解"）
4. **风格约束太松**: "不要过度展开" 不足以限制长度

## v2 设计原则

1. **Prompt 即规则，不解释**: 用命令式语言，不说"为什么"
2. **结构内化，不显式输出**: 要求模型内部执行 5 阶段流程，输出最终分析，不输出阶段标签
3. **长度硬约束**: 超过 2500 字后停止生成
4. **评分维度内嵌**: 在 prompt 中告诉模型"我重视什么"，让模型主动优化

## v2 Prompt 设计

```
你是一个深度分析引擎。分析问题时必须：

1. 识别问题类型（社科/哲学/系统设计/跨学科），选择对应的分析框架
2. 拆解问题，识别所有关键变量及其关系
3. 区分因果和相关，提出替代解释
4. 明确边界条件和失效点
5. 标注每个结论的不确定度（高/中/低）

要求：
- 中文优先，简洁直接
- 先结论后论证
- 不要废话，不要重复
- 不超过 2500 字
- 不要输出分析过程本身，直接给出分析结果
```

**字符数**: ~180 字符（vs v1 的 ~900 字符）
**设计意图**:
- "先结论后论证": 对应成璐风格（先证据后结论的反面 — 在分析中先给框架再展开）
- "不要输出分析过程本身": 避免 v1 的元注释问题
- "不超过 2500 字": 硬约束，配合 max_tokens=3000

## v2 评分修正

当前评分机制的问题：
1. **length_penalty 太弱**: 2500-5000 字之间扣分线性但太慢
2. **深度评分太依赖关键词**: 可以通过堆砌关键词刷分
3. **缺少"结论质量"维度**: 模型可能分析结构完整但结论空洞

修正后评分：
```python
# 新增 dimension: conclusion_density
# 结论句的比例 = 有断言性的句子 / 总句子数
# 过低（<0.1）→ 全是描述没有判断 → 扣分
# 过高（>0.8）→ 全是断言没有论证 → 扣分
# 最佳区间: 0.2-0.5

# 新增 dimension: insight
# 包含"不是...是..."或"关键不在于...而在于..."这类判断性语句 → 高分
# 只有描述性语句 → 低分

# 减少 length_penalty 权重: 0.5 → 0.3
# 增加 conclusion_density 权重: 0.8
```

## 预期结果

如果 v2 设计正确：
1. v2 > v1：相同分析质量，更少的 token 浪费
2. v2 > method_only：method_only 没有强制结构，有时缺少边界条件
3. v2 > persona：persona 没有分析框架，只是身份描述
4. v2_strict > v2：严格字数限制提高信息密度
