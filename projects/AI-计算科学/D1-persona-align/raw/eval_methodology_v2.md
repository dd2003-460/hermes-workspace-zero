## 一、现有 eval 的根本缺陷

### 现有评分机制（V1）

6 个维度，全部依赖关键词匹配：

| 维度 | 判断方式 | 问题 |
|---|---|---|
| block_structure | 有没有编号列表/❏ | 写 3 条 ≠ 有分析 |
| question_ratio | 有没有反问号 | 反问 ≠ 真追问 |
| cross_domain | 有没有跨学科关键词 | 提了名字 ≠ 有见解 |
| uncertainty | 有没有"可能/但/未必" | 说了"可能" ≠ 真正不确定 |
| depth | 缺少负面关键词 | 没提反例 ≠ 没考虑过 |
| length_reasonable | 长度阈值 | 长 ≠ 深 |

**核心问题**：测的是"表面风格"，不是"分析能力"。

一个回答写了几条编号、出现了一些"可能/但"，就得到 0.7 的分数。
另一个回答真正做了变量分解和统计设计控制，但因为没用编号、没写反问号，分数更低。

这是**指标对齐**——模型学会了"怎么拿高分"，不是"怎么分析得好"。

### 现有问题（5 个）

1. 男女在数学天赋上是否存在差异？如何区分先天禀赋和后天环境的影响？
2. "信息+选择压力→智能"是否是必然推论？还是只是偶然工程产物？是否存在与实现无关的智能原理？
3. 如果让一个 AI agent 独立完成一个大型工程项目（如 coding 任务），它需要具备哪些核心能力？如何评估它的规划能力是否充分？
4. "概率是动力学下的信息抹除"——这个观点在什么条件下成立？它和贝叶斯概率诠释的根本区别是什么？
5. 语言、数学、物理、社会是否真的是同一套信息处理机制的不同表现？如果可以统一，统一的框架应该满足什么条件？如果不能，边界在哪里？

**这些问题本身是好的**——都是经典复杂问题，no trivial answers。
问题出在**怎么评判回答**上。

## 二、成璐的评价标准（原始输入）

> **原话 1**：
> "需要我给你标准的问题和回答点评分标准吗
> 
> 例如，评估男女天赋，应该集中考虑环境，影响，相关变量侧面信息，尝试采用统计方法排除环境影响加分，这样？"

> **原话 2**：
> "或者考虑tokens产率性价比，列出金钱，prefill，decode，然后分析场景，分析适配和最优化加分？"

> **原话 3**：
> "你觉得优化思路好吗，值得加分吗"

> **原话 4**：
> "以及有没有什么统一通用方法论，判断问题类别，考虑已有针对性流程，考虑是否有更好优化，适配？"

### 原话解析

**原话 1 的核心要求**：
评估"男女数学天赋差异"时，正确的分析路径是：
- **集中考虑环境因素**——这是主要混杂变量
- **考虑相关变量的侧面信息**——不仅仅是"男女差异"这个表面问题
- **尝试采用统计方法排除环境影响的加分效应**——设计能隔离因果的分析框架

这不是一个"列出几点可能性"的回答，而是一个**设计可操作分析方案**的任务。

**原话 2 的核心要求**：
评估"优化策略性价比"时，正确的分析路径是：
- **列出金钱成本**——不仅是 token 数，是实际费用
- **区分 prefill 和 decode 成本**——这是不同的计算模式，成本结构完全不同
- **分析场景**——不同场景（在线推理、离线训练、边缘部署）的约束完全不同
- **分析适配和最优化**——不是"选哪个更好"，而是"这个场景下最优化方案是什么"

这也不是"各有优劣"的回答，而是一个**建模+场景分析**的任务。

**原话 3 的核心要求**：
成璐在问：**提出统一方法论本身是否值得加分？**
答案是：值得。因为这涉及**元认知能力**——不只是解决问题，而是考虑"解决问题的方法对不对"。

**原话 4 的核心要求**：
成璐在提出一个具体的方法论框架思路：
- **判断问题类别**——这不是问题类型的问题，而是问题分类体系的设计
- **考虑已有针对性流程**——对已知的每类问题，是否有成熟的分析流程？
- **考虑是否有更好优化、适配**——现有流程是否最优？有没有更适合当前场景的适配方案？

## 三、V1 vs V2 对比：不是迭代，是范式转换

| | V1（现有） | V2（提议） |
|---|---|---|
| **测什么** | 表面风格（编号、反问号、关键词） | 分析能力（变量分解、因果推断、建模） |
| **怎么评** | 自动关键词匹配 | 质量判断（需要人工或 judge 模型） |
| **评分粒度** | 0 或 1（一刀切） | 分层（从浅到深连续谱） |
| **例子：男女天赋** | 有没有提到"社会建构" | 有没有识别混杂因素、提出排除方案 |
| **例子：优化** | 有没有提到"成本" | 有没有区分 prefill/decode、建模场景约束 |
| **元认知** | 无（完全缺失） | 独立加分项（评估方法本身） |
| **可操作** | 不要求 | 核心要求（分析应能指导实际决策） |
| **区分度** | 低（0.65-0.75） | 待验证 |

## 四、统一方法论框架（V2 核心设计）

成璐提出的核心思路是：建立一个**统一通用方法论**，用于判断问题类别、选择分析流程、并评估是否还有更好的适配方案。

这个思路本身就代表了**最高阶的分析能力**：

```
输入问题 → 分类 → 匹配方法 → 执行分析 → 评估方法适用性 → 考虑替代方案
```

### 三阶分析流程

```
Level 0: 问题分类
         ↓
Level 1: 方法执行
         ↓
Level 2: 方法元评估
```

#### Level 0 — 问题分类（成璐说的"判断问题类别"）

判断问题属于什么类型，决定分析方向。

**成璐的标准**：一个回答如果能正确分类问题，说明它真正理解了问题的本质，而不是在套用模板。

| 类型 | 标志 | 适用方法 |
|---|---|---|
| 因果推断 | "X 是否导致 Y" | 混杂控制、自然实验、工具变量 |
| 概念辨析 | "什么是 Z？" | 定义边界、反例构造、同构 vs 类比 |
| 优化问题 | "怎么做最好？" | 成本建模、约束分析、场景适配 |
| 元问题 | "如何评估 X？" | 元框架设计、评估指标选择 |
| 还原论问题 | "能否统一到 A？" | 层级约化、反约化论证、涌现性 |
| 概率/认识论 | "概率的本质是什么？" | epistemic vs ontic、粗粒化、先验选择 |

#### Level 1 — 方法执行（成璐说的"考虑已有针对性流程"）

对应每个问题类型，检查回答是否执行了正确的方法。

**成璐的标准**：
- 因果推断问题：是否识别了混杂因素？是否提出了排除方案？是否区分了相关与因果？
- 优化问题：是否区分了 prefill/decode 成本？是否建模了不同场景的约束？是否量化了 tradeoff？
- 概念辨析：是否给出了清晰定义？是否构造了反例？是否讨论了边界条件？

#### Level 2 — 方法元评估（成璐说的"考虑是否有更好优化、适配"）

这是最高阶的能力，也是 V1 完全缺失的。

**成璐的标准**：
- 是否意识到所使用方法可能不适用？
- 是否考虑了替代方法及其优劣？
- 是否在方法选错时自我修正？

**成璐明确指出**：这个维度本身就值得加分。因为它代表元认知能力——不仅解决问题，还评估解决过程本身。

## 五、V2 评分标准设计原则

### 原则 1：不问"有没有"，问"对不对"

| V1（不问"对不对"） | V2（只问"对不对"） |
|---|---|
| 有没有提到"混淆因素"？ | 混淆因素识别得对不对？漏掉了哪些？ |
| 有没有提到"成本"？ | 成本建模对不对？区分了 prefill/decode 吗？ |
| 有没有"可能/但"？ | 不确定性判断合理吗？还是为了凑分瞎说？ |
| 有没有编号列表？ | 分析结构合理吗？拆分子问题了吗？ |

### 原则 2：要求可操作

分析应该能指导实际决策，不是纯理论讨论。

- 差： "可能有多种因素，需要进一步研究"
- 好： "需要控制家庭 SES，建议使用双胞胎研究设计排除遗传混杂，北欧数据已经提供了自然实验条件"

### 原则 3：分层评分

不是 0/1，而是分层：

- **0**：分析方向完全错误，或没有实质分析
- **1**：有分析但方向不对（比如用相关性替代因果）
- **2**：方向正确但执行不完整
- **3**：方向正确，执行完整，但未触及本质
- **4**：方向正确，执行完整，触及本质，有原创性观点

### 原则 4：独立评估每层

L0 错 ≠ L1 自动错。如果模型选了另一条路且论证充分，应该给分。

**例子**：一个回答把"男女数学天赋"分类为"统计推断"而非"因果推断"，但如果它正确讨论了方差差异 vs 均值差异，识别了教育作为混杂因素，应该给分。

## 六、初步评分维度表

| 维度 | 成璐的对应要求 | V2 评分方式 |
|---|---|---|
| **问题分类正确性** | "判断问题类别" | 0-4 分层：是否识别了真正的问题类型 |
| **方法匹配度** | "考虑已有针对性流程" | 0-4 分层：选的方法是否适合 |
| **分析深度** | "集中考虑环境/变量/侧面信息" | 0-4 分层：是否执行了深度分析 |
| **可操作** | "采用统计方法排除影响" | 0-4 分层：分析能否指导实际决策 |
| **场景适配** | "分析场景、适配、最优化" | 0-4 分层：是否考虑了场景差异 |
| **元评估** | "考虑是否有更好优化" | 0-4 分层：是否评估了方法本身 |

### 加权策略（待确认）

建议：L0 正确性 > L1 匹配度 > 可操作 > 场景适配 > 元评估（加分项）

因为：方向错误的话，深度分析再多也没用。
