# 推理 vs 背诵：区分评测设计

> # origin: human + ai整理
> # date: 2026-05-22

## 问题诊断

9B 回答在优化问题上：
- 区分了 prefill（计算密集）和 decode（访存密集）→ **教科书知识**
- 给出了 PagedAttention、Speculative Decoding 等术语 → **教科书知识**
- 场景策略完整但泛泛 → **背诵套路**

**缺失的关键维度**：
- **输入长度 vs 输出长度的影响**：prompt 长（prefill 主导）vs 生成长（decode 主导）的场景完全不同
- **上下文复用**：RAG 场景下 prefill 可以缓存，creative writing 不行
- **kv cache 大小与序列长度的关系**：这是影响 decode 成本的核心因素，但回答没有讨论

**本质问题**：模型在"回答已知类型的问题"，不是在"分析当前问题"。

## 推理 vs 背诵 的区分

| | 背诵模式 | 推理模式 |
|---|---|---|
| 触发条件 | 识别出"这是优化问题" | 即使识别出来，也追问"这个场景下真的适用吗？" |
| 回答特征 | 引用术语和标准答案 | 从第一性原理推导 |
| 对异常的敏感 | 忽略异常 | 主动讨论"什么情况下标准答案不成立" |
| 元认知 | "这是我的结论" | "我用了这个方法，让我验证它是否适用" |

## 如何激活推理而非背诵

**原则 1：不给标准问题的标准问法**

不要问"请你评估优化性价比，按以下步骤分析"——这直接告诉模型"这是个优化问题"，模型就会切换到"背诵模式"。

改为：
- 给出一个具体场景，让模型分析
- 不给问题分类的提示
- 不预设分析框架

**原则 2：加入认知冲突**

在问题中埋入与标准知识矛盾的前提，迫使模型重新思考：
- "有用户反馈说他们的 decode 阶段比 prefill 阶段更慢，尽管 decode 是逐 token 生成的。这可能吗？为什么？"
- "一个 1000 token prompt + 50 token 输出的场景，总成本可能比 10 token prompt + 500 token 输出的场景高吗？"

**原则 3：要求从第一性原理推导**

"不要引用任何已知的优化技术（PagedAttention、speculative decoding等）。从 GPU 硬件特性（计算单元、内存带宽、cache）出发，分析 LLM 推理的成本结构。"

**原则 4：强制探索替代路径**

"列出你认为可能的分析路径。然后逐条评估每条路径的可行性。最后说明为什么选当前路径。"

## 实验设计

需要设计一组问题，专门测试"能否在未知场景中推理"而非"背诵已知答案"。

### 测试组 A：标准问题（背诵基准）

这些是模型训练数据中可能见过的标准问题，用于评估背诵能力。

### 测试组 B：认知冲突问题（推理触发）

这些问题包含矛盾前提或反直觉现象，需要模型从第一性原理推导。

### 测试组 C：陌生场景问题（泛化能力）

这些问题涉及训练数据中不常见的场景组合。
