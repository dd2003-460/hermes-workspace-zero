1. 词汇重复
"模型"、"框架"、"工具"、"记忆"是反复出现的词组，约有 20/80 条消息涉及其中至少一项。例如：“框架和模型不是也影响的吗，记忆管理现在似乎是分层+向量，但是工具啊这些都要我告诉规则吗， 3月19日”。
英文技术词与缩写的覆盖面较广，约 25/80 条消息含有一项或多项，例如：“Stress-test the B200/H200 cluster sizing audit: model footprint, TP/PP topologies, and memory overhead across Llama 3 405B and DeepSeek-V3”，以及“你说的生成阶段，是decode吗，也就是带宽瓶颈？”
询问来源、验证和不确定性的词组重复出现，例如“可核验一手/权威来源线索(URL+日期)”“证据不足就明确说‘证据不足’，不要猜测”。这些约束语常与任务要求并列。

2. 话语标记和连接词
"那么"常用于引出下一个问题或从前提转到推论，例如：“那么是否有人决策会用一些可信论文结论？”。
"但是"、"不过"、"如果"和"也许"用于限定前句或提出分支，例如：“但是人为什么会突然自查，也是因为习惯吗，那么把这个习惯刻入权重是否就可以”。
多个问题常以数字层级或连续问句组织，例如：“1.我很好奇百分比如何估算，百分比不同区间是什么用户画像 2.如果我表明我的意图是建立真正自动化但不依赖api……”。
结尾形式不固定：有的以问号结束，有的以具体指令结束，如“Reply with exactly the word WORKS_TEST”；也有带日期尾注的消息，如“3月19日”“3月28日”。
3. 句法结构
短指令与长复合消息并存。短消息包括“Click test with mouse event”；长消息则可能同时给出背景、限制条件、编号问题和期望输出，例如以“给 Gemini 3.1 Pro 的结构商量（AI Studio 咨询稿）”开头的书籍结构咨询。
一条消息中连续提问的形式较常见，例如：“你说的生成阶段，是decode吗，也就是带宽瓶颈？但是我不理解，qk是attention，或者生成，那么计算还是主要的，然后得到结果，在词表查输出，似乎也是常数时间？”
编号、分层小节和括号用于标示结构或补充说明，例如“1.1”“1.3.5”“Q1（最重要）”以及“（长期记忆，例如我身份等）”。消息里也会嵌入表格、公式或英文命令。
标点组合较灵活：中文逗号与问号用于串联问题，括号用于插入限定，斜线用于并列缩写。例如：“TP/PP topologies”“memory bandwidth”“（作者/年份/标准名）”。部分测试文本无中文标点，直接使用英文句式。
4. 正字法和个人约定
中英混排明显，大小写形式并存，例如“ai”“AI”、“api”“API”、“moe”“MoE”，以及“GPU”“RAG”“SFT”“CDP”。可见写法会随词项和消息变化，而非全篇统一采用一种大小写格式。
技术标识符通常保持英文原貌，如“decode”“attention”“memory”“presence_penalty”“streaming mode”“pytest”。例如：“请对以下7项GPU硬件规格做交叉核实。”
日期、版本号、单位和数字直接嵌入正文，例如“2026-09-25”“1.44TB”“80GB”“3月28日”。编号也承担层级作用，如“1.1”“1.2”“1.3.5”。
句内空格使用不完全一致。英文单词与中文之间有时无空格，如“ai自动化控制电脑”；有时按英文原格式留空格，如“Reply with exactly the word WORKS_TEST”。
[弱] 可见到个别英文拼写或大小写形式不统一的情况，但没有足够证据将其归为稳定错误；例如“claudecode的多agent呢”仅是单条消息中的写法。
5. 语气与语域
请求方式常直接说明要做什么，例如：“我希望详细了解通过ai自动化控制电脑，你先给我这个下面完备的项目，然后分别介绍”。也会明确规定回答边界，如：“证据不足就明确说‘证据不足’，不要猜测。”
口语表达与正式任务说明并存。口语例子是：“算了，我还是cron定单agent然后让他按loop走吧”；任务说明则可包含标题、范围、交付形式和核验要求，例如“GPU推理硬件选型2026，请给出可核验一手/权威来源线索(URL+日期)与适用条件/不确定性，不要只结论”。
有些消息用明确的否定或纠正句式，例如：“不，他的跑是有具体反馈和努力的，是我设计的具体loop流程”。形式上通常先否定前一说法，再提出限定或补充。
英文命令式短语与中文请求同时出现，例如“Track live GPU rental prices across Lambda, RunPod, and AWS for H200 and Blackwell instances with weekly spot-rate alerts”与“请用一句话回复：llm-gatherer CDP 自动化成功”。
6. 文本推理模式
常见表达结构是“提出问题—列分项—要求核验或比较”。例如：“请对以下7项GPU硬件规格做交叉核实。每项回答：确认/否定/不确定 + 可引用来源URL。”这种结构把输出字段预先写入消息。
多层编号用于递归组织问题，常见形式包括“1.1”“1.2”“1.3.5”，随后再用“Q1”“Q2”或“(1)(2)(3)”分组。例子：“本阶段强制递归分解方法：先分解目标→因素；对每个因素区分人类已提供/项目可推导/仍需研究条件；写边界/优先级/影响”。
句内常保留条件和自我修订，例如：“不，他的跑是有具体反馈和努力的，是我设计的具体loop流程 具体要不要肯定要，但思考我的需求和方向是ai自主最主要的部分吧... 也许你有别的看法？”原文里的省略号是该消息本身的标点，呈现了补充语句接续前句的写法。
