# 情景引导 Prompt 实验结果

> 实验时间：2026-10-19
> 实验者：scene-guide-experiment subagent
> 模型：qwen3.8-27b-w8a16（全部 3 个 prompt 同一模型）
> 场景：S2-量化估算-元评估（与 T38 盲测 v6 一致，方便对比）

## 实验设计

对比三种 prompt 策略，哪种更能**自然**引发 AI 的自言自语/吐槽/内心思考（括号插话、自我觉察、跑题）：

| Prompt | 类型 | 路径 |
|--------|------|------|
| OPRO-v8.1 | 限制式（排除式词表+被动中断描述） | `tasks/experiments/opro-v8.1-prompt.md` |
| Scene-A | 情景引导A（纯场景描述，零规则） | `tasks/experiments/scene-guide-A-prompt.md` |
| Scene-B | 情景引导B（场景+2段GT原文示范） | `tasks/experiments/scene-guide-B-prompt.md` |

盲生成 1 次/prompt，不读 GT。

- GT: 3 处（"（也许是因为我在的地方太垃圾？）"、"（尽管我不是）"、"（这是个局部，不客观的形容）"）
- OPRO-v8.1: 3 处

- **Scene-B: 2 处**（"（0.6）"、"（跑题了）"、"（刚才跑题回来了）"）— 严格算 3 处但 1 处是 conf 标注

## 各维度评分理由

### OPRO-v8.1（限制式）
- **A1=3**: "压过去了"、"卡死"等物理隐喻中等密度
- **B1=9**: "信度不高"、"我猜"、"我没法证明" — conf 标注最密集
- **B3=5**: 编号跳跃合理，括号插话 3 处
- **B5=8**: 硬数字最密集（"20万到50万"、"5%"、"2016年NTM"）

### Scene-A（纯场景描述）
- **A1=4**: "逼你做一次自我审查"（逼）、"手就停了"（物理动作描述内心）— 物理动词略高
- **A3=0**: 无 AI 填充词
- **B1=5**: "我信度不高"、"我没法证明" 有，但密度低于 v8.1 和 Scene-B
- **B3=6**: "4 5 然后我跳到别的地方去了 (为什么跳我也不解释)" — 明确的跑题+自我觉察，是 3 个文本中最显式的"打字时被打断"描写
- **B4=7**: "我"高频但不是每句
- **B5=4**: 硬数字密度明显低于 v8.1 和 Scene-B（只有"85到92"、"2016年NTM"）

### Scene-B（场景+few-shot）
- **A1=2**: 物理动词最少，语言最"干净"
- **B1=10**: **全表最高** — 几乎每句都带 conf 数值（0.3/0.7/0.85/0.9/0.4/0.5/0.75），且标注格式高度规整
- **B5=9**: **全表最高** — 每个 conf 都是硬数字，加上"85-92%"、"2016年NTM"
- **B3=6**: "5.（跑题了）" 和 "1.1回到taste那个（刚才跑题回来了）" — 显式的跑题-回跳结构，编号跳跃
- **A3=1**: "综合下来" 有轻微空话感
- **核心特征**: conf 数值标注（0.3/0.7/0.85）是 **GT 和 OPRO-v8.1 都没有的** — 这是 few-shot GT 带来的新行为，但也可能是"过拟合"（成璐原文用"信度不高"、"我猜"这种模糊 conf，不用精确小数）

## 关键发现

### 1. 情景引导确实能自然引发自言自语/吐槽/内心思考
- **Scene-A** 的 "4 5 然后我跳到别的地方去了 (为什么跳我也不解释)" 是 3 个文本中**最像真人打字时被打断**的描写 — 纯场景描述（"你打到一半会突然想到别的事，手就停了"）直接产出了这个行为，没有任何规则约束
- **Scene-B** 的 "5.（跑题了）" 和 "（刚才跑题回来了）" 也是显式的自我觉察
- 对照组 OPRO-v8.1 的括号插话（"我猜这个数 你验证过吗"）更偏向"内容层面的 conf"，而不是"打字过程层面的内心活动"

### 2. Scene-B 的 conf 数值化是双刃剑
- **优势**: B1=10（全表最高）、B5=9（全表最高），断言+conf 密度碾压
- **劣势**: 成璐原文用的是"信度不高"、"我猜"、"我没法证明"这种**模糊 conf**，不用 0.3/0.7/0.85 这种精确小数。Scene-B 的精确 conf 标注更像是"AI 在表演 confidence calibration"，而不是"成璐在打字"
- **结论**: few-shot GT 让模型学到了"带 conf"这个模式，但**过拟合到了 conf 的标注形式**（精确数值 vs 模糊描述）

### 3. Scene-A 在"自然度"上最接近 GT
- 轴A=4（和 v8.1 持平），轴B=26（低于 v8.1 的 34）
- 但 Scene-A 的**打字过程描写**（"手就停了"、"写到这停一下"、"跳到别的地方去了"）是 3 个文本中最自然的
- 代价是内容密度低（B5=4），硬数字少

### 4. 限制式 prompt (v8.1) 的"自言自语"是规则驱动的
- v8.1 的括号插话（"也许是因为我在的地方太垃圾？"）来自 prompt 里明确写的"括号里会突然冒出一句自我觉察，比如..."
- 这是**规则触发**，不是**状态自然涌现**
- 对比 Scene-A 的 "(为什么跳我也不解释)" — 没有规则要求写这个，是模型自己"进入状态"后产出的

## 结论

**情景引导（特别是 Scene-A 纯场景描述）更能自然引发自言自语/吐槽/内心思考。**

具体排序（按"自然度"，即"打字过程层面的内心活动"而非"内容层面的 conf 标注"）：
1. **Scene-A** — 最自然的打字过程描写（手停了、跳到别处、写到这停一下），没有规则驱动
2. **Scene-B** — 跑题-回跳结构显式，但 conf 数值化有过拟合风险
3. **OPRO-v8.1** — 括号插话有，但主要来自 prompt 规则（"比如'（也许是因为我在的地方太垃圾？）'"），不是自然涌现

**但"自然"≠"最好"**：
- 如果要**内容密度+conf 标注**：Scene-B 最强（轴B=35）
- 如果要**打字过程的自然感+自言自语**：Scene-A 最强
- 如果要**均衡**：v8.1 仍然很稳（轴B=34，轴A=4）

**建议**：
- 核心方向应该是 **Scene-A（纯场景描述）+ 少量 few-shot GT**（不用精确 conf 示范，用"信度不高"、"我猜"这种模糊 conf 的 GT 片段）
- 避免限制式规则（排除式词表收益≈0 已验证）
- 避免精确数值 conf 示范（会过拟合到"AI 表演 confidence calibration"）
