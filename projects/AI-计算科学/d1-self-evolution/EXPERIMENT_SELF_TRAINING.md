# 自我训练进化实验

## 核心问题

用户明确指出：Agent 的三大稳定性问题
1. **注意力不稳定** — 上下文压缩后重复做同样的事
2. **记忆不稳定** — 声称搜索了不存在的目录，记忆写入不准确
3. **动作不稳定** — 承诺做某事但实际没做，或做了却说没做

## 消融实验证据

D1-automation/abli_experiments 已证明：
- 通过 MLX 消融可以修改 LLM 的"置信度驱动决策"倾向
- 消融后模型在任务模糊时更倾向于追问确认
- 消融强度可调 (0.5-1.5)
- 方向可调 (增强 vs 降低)

关键发现：**Agent 的行为倾向不是不可改变的 prompt 问题，而是可以通过模型权重微调的物理属性。**

## 自我训练进化框架

### 目标

创建一个系统，让 Agent 能够：
1. **记录自己的动作轨迹**（注意力、记忆、决策）
2. **分析轨迹中的不稳定模式**
3. **通过消融或微调修复不稳定**
4. **验证修复效果**
5. **循环迭代**

### 核心组件

#### 1. 动作轨迹记录器

每次 Agent 执行操作后，记录：
- 用户请求
- Agent 的理解（实际解析出的意图）
- Agent 的决策（选择哪个工具/操作）
- Agent 的执行结果
- Agent 的自我评估（置信度、完成状态）

格式：JSONL 日志，每条记录包含：
```json
{
  "timestamp": "2026-05-10T02:24:00Z",
  "user_request": "找一下mlx相关的消融实验",
  "agent_understanding": "在user/mlx-abl下搜索",
  "agent_decision": "调用terminal执行查找",
  "actual_path": "/Users/a1-6/D1-automation/mlx-abliteration/",
  "result": "未找到（因为路径错误）",
  "confidence": 0.85,
  "self_assessment": "已完成",
  "error_detected": false
}
```

#### 2. 轨迹分析器

定期分析轨迹，识别：
- 意图理解错误率（理解 vs 实际意图）
- 路径/资源选择错误率
- 置信度-结果偏差（高置信但错误）
- 重复行为模式

#### 3. 消融修复器

基于分析结果，确定需要修复的行为倾向：
- 如果意图理解错误率高 → 增强"追问确认"倾向
- 如果路径选择错误率高 → 增强"先验证路径存在"倾向
- 如果高置信但错误 → 降低置信度阈值

#### 4. 验证器

对比修复前后的行为差异：
- 相同的请求/场景下，Agent 的新反应
- 关键指标：错误率、追问率、自主执行率

## 实验计划

### 阶段1：数据采集（当前）

从历史对话中提取动作轨迹：
- 所有 user→agent 的请求
- agent 的实际理解和执行
- 对比实际结果和声称结果

### 阶段2：模式分析

识别不稳定的具体模式：
- 哪些类型的请求最容易理解错误？
- 哪些类型的错误最频繁？
- 置信度与正确性的关系？

### 阶段3：消融实验设计

基于分析结果设计消融实验：
- 确定目标倾向（如"路径验证"、"意图确认"）
- 准备正/负数据集
- 选择消融强度和层数

### 阶段4：训练与验证

执行消融实验并验证效果：
- 对比原始模型和消融模型
- 记录关键指标变化
- 迭代调整

## 与现有消融实验的关系

| 现有实验 | 方向 | 局限 |
|----------|------|------|
| D1-confidence | 置信度驱动决策 | 未验证实际效果 |
| D1-refusal | 拒绝倾向 | 与当前问题无关 |
| **本实验** | **注意力/记忆/动作稳定性** | **需要建立闭环** |
