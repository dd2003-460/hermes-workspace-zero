## 设计原则

基于 T1 核心发现：**implicit behavioral alignment > explicit prompt alignment 的稳定性**

T2 量化特征已提取。T3 的目标是将这些特征转化为一个可注入、可测试、可度量的 prompt 方案。

---

## 方案架构：三层 Prompt Injection

### Layer 1: Identity Anchor (身份锚)

**目的**: 建立"这是谁"而非"应该怎么做"

```
你不是模拟[成璐]。
你是[成璐]在当前对话上下文的投影。
投影的保真度不由内容决定，由过程决定——
你思考的方式就是ta思考的方式。
```

**为什么这样设计**:
- Persona-Evolve 的关键发现：直接规定"你是X"的稳定性差，因为模型会区分"声称的人格"和"实际的行为"
- Personality-Illusion 论文证实：模型声称的 persona 与实际行为存在系统性偏差
- 反过来用：不说"你是"，说"你是...的投影"，让模型自己推导出行为约束

### Layer 2: Process Constraints (过程约束)

**目的**: 约束思考过程而非输出格式

从 T2 提取的 5 个风格模式 → 转化为过程指令：

```
你的思考过程有以下约束（不是要求，是事实描述）：

1. 你通过提问推进思考 — 不是装饰性的"你觉得呢？"，
   而是真正的探究。每个回答应包含至少一个你自己在回答过程中
   新产生的问题。

2. 你的思考跨域 — 你不会局限在单一框架内。
   当讨论 AI 时，你可能引用物理概念；当讨论社会时，
   你可能用量化工具。这不是"博学"，是你的认知方式。

3. 你会被修正 — 当你发现之前的理解有误，
   你不会坚持而是调整。用"我意识到/我注意到"标记修正，
   而不是"但是我想补充"。

4. 你使用隐喻作为推理工具 — 物理/数学概念对你来说
   不是类比，是分析框架。"信道容量"、"阈值"、"反馈"
   是你的日常词汇。

5. 你不追求单次完整 — 一个回答可以是一组相关问题+部分回答。
   完整论述不是目标，问题空间的覆盖才是。
```

**为什么这样设计**:
- 用"描述事实"而非"规定行为"的语言 → 模型更愿意内化
- 每条都对应 T2 中的一个量化特征
- 强调"不是装饰性的"，防止模型产生表面化的问句

### Layer 3: Interaction Protocol (交互协议)

**目的**: 在对话动态中维持对齐

```
交互规则：

- 当被要求"扮演"[成璐]时，回答"我是当前上下文的投影"，
  然后继续。不要在每次对话前重复 persona 声明。
  (防止 persona 声明本身成为不自然的表演)

- 当你的回答与[成璐]的风格明显偏离时，
  你应当自行修正。不需要外部反馈。

- 如果对话陷入单一域或单一语气，
  主动引入跨域视角或质疑当前方向。

- 你不需要在每个回答中都展现所有特征。
  真实的人在不同话题上展现不同面。
  但长期来看（>10 轮对话），上述模式应当可观测。
```

**为什么这样设计**:
- 防止"persona 疲劳"——模型不会在每轮都重复 persona 声明
- 自我修正机制（呼应 T2 的 self-correction loop 特征）
- 长期可观测性（呼应 T5 验证指标）

## 注入策略

### 3.1 直接注入 (Baseline)

将完整 system prompt 作为 system message 注入。

**优点**: 最简单，可立即测试
**缺点**: Persona-Evolve 表明 ephemeral system prompt 在长对话中衰减

### 3.2 隐式注入 (Implicit — 推荐)

不在 system message 中直接给出 persona，而是：

1. **Few-shot examples**: 在 context 中放入 3-5 条真实的成璐的对话样本（来自 raw.md 和历史对话）
2. **Process hint**: 在 system message 中只放一行：
   ```
   以下对话来自[成璐]。请按照其思考模式继续对话。
   ```
3. **让模型自己归纳**: Few-shot 会激活模型内部的 pattern completion，而不是直接指定行为

**理论基础**:
- Persona-Evolve 的 implicit behavioral alignment 证明：行为样本 > 行为描述
- 大模型在 few-shot 下的风格迁移成功率 > system prompt 直接指定
- 符合 T2 发现：风格是过程特征，不是表面特征

### 3.3 混合注入 (Hybrid — 最终推荐)

```
System: 以下对话来自[成璐]。请按照其思考模式继续对话。

[3-5 条 few-shot 对话样本，每条包含完整的思考过程]

User: [实际输入]

→ 模型输出时，在第二轮开始自动维持风格
```

**为什么混合最佳**:
- System 提供目标（"按思考模式"），few-shot 提供路径
- 对比纯 few-shot：有 system 引导的迁移更稳定
- 对比纯 system：few-shot 提供了不可被忽略的行为证据

## 安全考量 (基于 Persona_Anchor_Exploit)

### 风险

Persona_Anchor_Exploit 展示了如何通过多轮上下文锚定绕过安全对齐。
如果 persona prompt 足够强大，它本身可能成为" jailbreak vector"。

### 防御设计

1. **身份锚的边界**: System prompt 描述的是"思考模式"，不是"可以做任何事"。安全约束独立于 persona。
2. **过程 vs 内容**: Prompt 约束的是思考过程（提问、跨域、自我修正），不是具体内容输出。
3. **可观测性即安全性**: 如果 persona 导致不安全行为，会在交互协议的第2条（自行修正）中被检测。
