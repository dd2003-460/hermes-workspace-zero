# 阶段 01 · 目标、因素与空缺条件

任务：调研性价比最高的本地大模型推理 GPU（性价比 = 推理性能/价格，追求单位价格下的最大推理性能）

## 当前阶段工作记录

按照当前阶段的外部规则文件完成工作；这里记录实际过程、证据、产出和未解决问题。

### 目标定义

**交付物**：推荐一款性价比最高的本地大模型推理 GPU

**性价比定义**：
- **显存容量**：硬性门槛（0/1 约束）— 显存不足 → 模型无法加载
- **推理速度**：优化指标（线性收益）— 速度越快 → 用户体验越好
- **性价比公式**：性价比 = 推理性能 / 价格，追求单位价格下的最大推理性能
- **无预算约束**：不限制价格上限，所有候选 GPU 按性价比排序，性价比最高的即为最优选择

### 因素分解

#### 1. 显存容量（优先级：高 — 硬性门槛）

- **边界**（基于量化格式的显存需求计算）：
  - 8GB：可运行 7B 模型（4-bit 约 4-5GB，FP16 约 14GB 不够）
  - 12GB：可运行 7B 模型（FP16），或 13B 模型（4-bit 约 7-8GB）
  - 16GB：可运行 13B 模型（FP16 不够，需 4-bit），30B 模型（4-bit 约 15-18GB，勉强）
  - 24GB：可运行 13B 模型（FP16 不够，需 4-bit），可运行 30B 模型（4-bit 约 15-18GB），**不可直接运行 70B 4-bit（需 35-40GB）**
  - 40GB+：可运行 70B 模型（4-bit 量化），或多模型并发
- **影响**：显存不足 → 模型无法加载或必须量化/分页（性能损失）
- **已知**：用户需要运行大模型（具体模型大小待确认）
- **未知**：用户目标模型的具体大小和量化需求

#### 2. 推理速度（优先级：高 — 优化指标）

- **边界**：
  - tokens/sec > 10：可用（可接受延迟）
  - tokens/sec > 50：良好（实时交互）
  - tokens/sec > 100：优秀（流畅体验）
- **影响**：速度慢 → 用户体验差，无法实时交互
- **已知**：无
- **未知**：各候选 GPU 的实际推理速度

#### 3. 显存带宽（优先级：中）

- **边界**：HBM > GDDR6X > GDDR6
- **影响**：带宽低 → 推理速度慢，尤其对大模型
- **已知**：无
- **未知**：各候选 GPU 的显存带宽具体数值

#### 4. 软件生态兼容性（优先级：高）

- **边界**：CUDA（NVIDIA）> ROCm（AMD）> Metal（Apple）
- **影响**：生态不兼容 → 需要额外适配，可能无法使用
- **已知**：主流框架（PyTorch、TensorFlow）对 CUDA 支持最好
- **未知**：用户现有软件栈和框架偏好

#### 5. 价格（优先级：高 — 性价比分母）

- **边界**：价格越低 → 性价比越高（但需同时考虑推理性能）
- **影响**：价格过高 → 性价比降低；价格过低 → 可能性能不足
- **已知**：无
- **未知**：各候选 GPU 的当前市场价格（全新/二手）

#### 6. 功耗/散热（优先级：中）

- **边界**：桌面级 vs 服务器级
- **影响**：功耗高 → 需要额外散热设备，电费高
- **已知**：无
- **未知**：用户现有电源功率和机箱尺寸兼容性

#### 7. 社区支持和文档（优先级：低）

- **边界**：GitHub stars > 1000, 近期有更新
- **影响**：社区小 → 问题难解决，文档少 → 学习成本高
- **已知**：NVIDIA CUDA 社区最成熟
- **未知**：AMD ROCm 和 Apple Metal 的最新支持状态

### 阶段 02 研究路径

**第 0 步：确认用户模型需求（并行进行）**

- 在调研 GPU 的同时，记录不同模型规模（7B、13B、30B、70B）在不同量化格式（4-bit、8-bit、FP16）下的显存需求
- 基于多种模型场景并行调研，确保覆盖用户可能的需求范围
- 显存需求参考公式：4-bit 量化约 0.5-0.6 GB/10B 参数，8-bit 约 0.9-1.0 GB/10B 参数，FP16 约 2 GB/10B 参数
