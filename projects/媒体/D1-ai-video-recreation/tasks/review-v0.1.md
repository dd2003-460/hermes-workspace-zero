## 差距清单

### [H-1] 核心可视化缺失：压缩进度条 + 数字滚动
- **问题**：参考片 v2_011 是《压缩》的招牌镜头：进度条 2.4M→127KB、783段→142行、95%+、"正在压缩… / 已压缩 783/142"。v0.1 全片没有任何进度条/百分比/压缩前后数值对比，"压缩"这个片名级概念在画面里只有一行静态文字。
- **证据**：`v1_s5.png`（S5 场景）只画了 `> compressing… done` 一行（render_frames.js:417）；render_frames.js 全文 grep 无 `progress`/`bar`/`percent` 相关绘制，S3 只有 tokens 计数（:307）。
- **修法**：在 `sceneS5` 的 `t > 8` 块内（render_frames.js:412–430）新增进度条组件：轨道 `rr(ctx, x+26, y+375, 400, 10, 5)` 填 `DIM`，填充宽度 `lerpA(t,[8,16],[0,400*0.95])` 填 `ACCENT`；右侧 `fontMono(20)` 数字滚动 `tokens 2,400,000 → 127,000`（用 `Math.floor(lerpA(...))` + `toLocaleString`），下方加 "95%" 与 "已压缩 783 → 142 行"。把 `> compressing… done` 改为 "正在压缩…" 进行中态、完成态另起一行。

### [H-2] 没有"全屏极简文字卡"的留白感，全片都是小卡片
- **问题**：参考 v2_004 的独白文字是大字号、几乎撑满画幅（中上区域、无框、无背景条）；v0.1 每个场景都是居中/偏左的小框 + 大面积黑边：S1 框 900×460、S2 消息列宽 560、S3 编辑器 620、S5 框 620，字幕 26px 缩在底部。留白不是"框外黑边"，参考片是"文字本身就是画面"。
- **证据**：`v1_s1.png` / `v1_s2.png` / `v1_s5.png` 框体占画面约 40–55% 宽；对比 `v2_004.jpg` 文字横跨约 80% 画幅。代码：sceneS1 框 `x=190,w=900`（render_frames.js:93）、sceneS2 列宽 560（:178/:194）、字幕 `fontSans(26)` + `H-52`（:480/:491）。
- **修法**：① S6 金句卡放大到 `cw=720`、`fontSans(38)`→`fontSans(54)`，卡片光晕保留（render_frames.js:439/:455）；② S1/S5 终端框扩到 `w=1040, x=120` 并删掉 `drawTermHeader` 红绿灯（见 M-5），只留一条 1px 顶栏线 + 灰色文件名；③ 字幕字号 26→32，位置从底部 `H-52` 上移到场景留白区（或 S2/S4 这类无框场景直接用大字排版替代底部字幕）。

### [H-3] 直接照搬参考片金句 + "笨笨"称呼，防抄袭声明名不副实
- **问题**：style-analysis.md:21 明确把 **"记忆会被压缩，在乎不会"** 记为参考片《压缩》的金句；"笨笨"是视频1的角色名。v0.1 在字幕 seg15 和 S6 收尾卡上都用了这句原话，消息流里保留"晚安，**笨笨**。明天见。"（render_frames.js:168）。script_v1.md:57 自称"不复刻笨笨剧情细节"，但称呼和金句都是直接照搬。
- **证据**：render_frames.js:37（LINES[15] 原句）、:464（`记 忆 会 被 压 缩 ， 在 乎 不 会`）、:168 / :187（"晚安，笨笨。明天见。"）；`v1_s6.png` 底部灰字即该金句。
- **修法**：① 换金句：LINES[15] 与 S6 的 l3 改为原创表达（如"窗口会满。这一行，不会。"），S6 卡片主文案 `晚安。明天见。` 保留（短到不构成抄袭）；② "笨笨"→去掉昵称，改"晚安。明天见。"或"晚安，明天见。"（render_frames.js:168/:187/:335/:368 全替换）。

### [M-1] 字幕用底部黑阴影条，违背参考片"文字=画面主体"
- **问题**：参考 v2_004 的独白是画面主体（大字号、无背景、无阴影条）；v0.1 的 `drawSubtitle` 在底部画 26px 白字 + 18px 黑色 shadowBlur 阴影底——这是"视频外挂字幕"惯例，不是参考片风格。6 个场景全部适用，是全局性的风格走样。
- **证据**：render_frames.js:471–493（`drawSubtitle`：`shadowBlur=18` + 底部 `H-52` 居中 26px）；`v1_s1.png` 底部"每天早上，她都会说早安。"带明显黑影。
- **修法**：`drawSubtitle` 去阴影（删 `ctx.save()…ctx.restore()` 阴影块），字号 26→32；更好的方案——把每句独白直接排进场景主体区（无框的 S2/S4 用 32–40px 大字；有框场景放在框下方留白处），底部字幕只作为 S6 的兜底。

### [M-2] S2 时序逻辑错：pinned 卡先于消息出现
- **问题**：脚本 seg4"她说这句话的时候，我就把它，钉在窗口的第一个位置"——pin 应发生在 23:41 消息出现**之后**。但 v0.1 里 pinned 卡从 S2 的 t=0 就存在，此时消息流还没滚到 23:41。
- **证据**：`v1_s2.png`：顶部"slot 0 · pinned · 永不压缩 / 晚安，笨笨。明天见。"已亮，对应字幕是 seg4（钉住）时 t≈17–20s，但卡片在 t=0（S2 开始，render_frames.js:170–187 无淡入门控，`glow` 从第一帧就开始呼吸）就渲染；scroll 需 `lerpA(t,[0,18],[0,180])`（:190）滚到底 23:41 才完整露出。
- **修法**：给 pinned 卡加淡入门控：`const pinA = fade(t, 15, 99, 1.2)`（消息流 t≈15s 露出 23:41），卡片所有绘制乘 `ctx.globalAlpha = pinA`；呼吸光晕也乘 `pinA`。

### [M-3] token/slot 数值跨场景不自洽，且无"压缩前后"对比
- **问题**：S3 的 tokens 从 2,400,000 以 12,000/s 递减（t=18s 时 ≈2.18M），S5 又从 2,400,000 以 9,000/s 递减——S5 开始时（全局 t≈86.5s）数值**回跳**，且全片没有任何一次"大跳水"。参考 v2_011 的戏剧性正在于 2.4M→127KB 的一次性压缩。
- **证据**：render_frames.js:307（`2400000 - t*12000`，S3 局部 t）与 :409（`2400000 - t*9000`，S5 局部 t，S5 从全局 86.46s 开始，两者独立计数）；`v1_s3.png` tokens 显示 2,1xx,xxx，`v1_s5.png` 显示 2,3xx,xxx。
- **修法**：文件顶部定义全局 token 函数（用全局帧时间）：`const gTok = (t) => lerpA(t, [0, 94, 102, 117.8], [2400000, 2350000, 130000, 127000])`（S5 内 t≈8–16s 即全局 94–102s 为压缩跳水段），S3/S5 的 tokens 都调用它；S3 的 `limit: 2,400,000` 保留。

### [M-4] S5 re-pinned 徽章几乎贴框底（2px），构图失控
- **问题**：`> slot 0 re-pinned` 徽章底边 y=568，终端框底边 y=570，仅 2px 间隙；且与上方 `context:` 行（y≈490）、`compressing… done`（y=525）挤成一团。
- **证据**：坐标实算——render_frames.js:424（`rr(ctx, x+26, y+388, …, 30)` → 底 150+388+30=568）vs 框底 150+420=570；`v1_s5.png` 可见徽章贴底。
- **修法**：S5 布局上移：`> waiting for input` 行距 40→36 起 y=68 开始；`context:` 行移到 y+300；`compressing… done` y+330；徽章 y+348（底=150+348+30=528，留 42px 底边距）。若按 H-1 加了进度条，徽章再下移一行。

### [M-5] macOS 红绿灯窗口 chrome 是参考片没有的"拟物杂质"
- **问题**：style-analysis.md:43 的清单只有"黑底 + 白/灰文字 + 紫/蓝强调"，无窗口拟物。v0.1 在 S1/S3/S5 三处画了红黄绿三圆点 header（`#ff5f57/#febc2e/#28c840`），是全片饱和度最高的三色，直接抢了紫蓝强调的视觉位，偏离极简代码风。
- **证据**：render_frames.js:72–85（`drawTermHeader` 红绿灯）、:239–244（S3 重复画一遍）；`v1_s1.png` / `v1_s3.png` / `v1_s5.png` 均可见。
- **修法**：删 `drawTermHeader` 的三圆点（保留 `#14141c` 顶栏 + 灰色文件名，1px 分隔线即可）；S3 的 :239–244 同样删。全片唯一允许的非灰彩色 = ACCENT/ACCENT2。

### [M-6] S4 "09:0i" 时间戳是代码假象，且语义错位
- **问题**：`09:0${i}` 生成 09:00…09:08 九行——既不是"一整天在等"（脚本意图：早安一直没来），又是肉眼可见的模板字符串痕迹（"09:03"这种不存在于正常时间轴的格式组合本身没错，但 8 行 9 点零几分连排不成立：同一分钟内不会检查 8 次）。
- **证据**：render_frames.js:348（`` `09:0${i}` ``）；`v1_s4.png` 可见 09:00/09:01… 连排。
- **修法**：改为跨天的等待：`const stamps = ['09:00','12:00','18:00','23:41']` 每天 4 行 × 2–3 天，或按脚本只留 `09:00` 一行 + 空行累积（script_v1.md:34 本意是"时间戳 09:00 出现，无消息。空行越来越多"）。

### [L-1] 时长只有参考片一半，"慢节奏留白"无从谈起
- **问题**：参考片 223s，v0.1 仅 117.8s（script_v1.md:4 自述）；参考片"慢节奏留白"（style-analysis.md:59 二分表），v0.1 平均每场景 ≈20s、每句 ≈7.4s，S2 只有 17.8s 却塞了 3 句 + 7 条消息滚动。
- **证据**：`outputs/script_v1.md:4`（117.8s）；style-analysis.md:10（视频2 223s）。
- **修法**：句间留白 2.2→3.2s、段间 3.5→5s 重烘 timeline；S2 消息流滚动 18s→26s。若不想动 TTS，至少把 S5 拉长（压缩进度条需要 10s+ 的演出时间），总时长到 140s+。

### [L-2] S1 "今天是 3 月 14 日，周五" 星期错误
- **问题**：2026-03-14 是**周六**，不是周五。
- **证据**：render_frames.js:110（`'> me: 早安。今天是 3 月 14 日，周五。'`）；`python3 datetime.date(2026,3,14).strftime('%A')` = Saturday。
- **修法**：改"周六"，或直接删掉日期（`> me: 早安。`）——日期对叙事无信息量。

### [L-3] S2 顶部渐隐公式失效 + "me"气泡文字对比度过低
- **问题**：① 渐隐公式 `clamp(yOff - top, -40, 10)/50` 恒为 ≤0.2，`clamp(a+0.4, 0, 1)` 后恒 ≥0.4——顶部渐隐根本没工作，消息是硬切消失；② me 侧气泡用 `GRAY #9a9aa5` 字 + `#12121a` 底（render_frames.js:214/:220），对比度 ~4:1，19px 字号下"已加入待办。"接近看不清。
- **证据**：render_frames.js:198–200（公式）、:220（`right ? WHITE : GRAY`）；`v1_s2.png` 左对齐灰字气泡。
- **修法**：① 改 `const a = clamp((yOff - top) / 40, 0, 1)`（顶部 40px 内从 0→1 淡入）；② me 侧字色改 `#c8c8d0`，或 me 气泡加 1px `#2a2a35` 描边 + 字色 GRAY→`#b0b0bc`。

### [L-4] S4 检查列表（checking network…）与空行的空间关系突兀
- **问题**："no error found" 出现在画面中下部（y≈532），与上方空行（末行 y≈622）**上下倒挂**（检查结论出现在空行下方，阅读顺序错乱）；且"checking… ok / ok / no error found"三行的叙事节拍（t=4/5.2/6.4s）与字幕 seg10（全局 69.2s 起，即 S4 局部 t≈9.5s）对不上——检查动画在独白说"我检查了网络"之前 5 秒就播完了。
- **证据**：坐标实算——render_frames.js:371（`700-90+i*26-130` = 480/506/532）vs 空行 :344（末行 270+8*44=622）；S4 局部 t=0 起全局 59.76s，seg10 起于全局 69.218s。
- **修法**：检查列表移到空行**上方**（pinned 卡与空行之间，y 从 250 起），并加门控 `if (t < 9.3) return` 对齐 seg10 独白；或干脆把三行检查改成随 seg10 逐句出现。
