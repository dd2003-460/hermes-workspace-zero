## 🔧 本地部署前先看这里

本项目只依赖 `numpy`, `scipy`, `sympy`, `mpmath` 四个第三方库。部署到本地
新环境时，建议先运行一键自检脚本：

```bash
python3 setup_check.py --install
```

它会自动检查Python版本、检查/安装依赖库、做真实计算的冒烟测试、并实际跑几个
代表性脚本确认整条链路可用。详细说明见 `部署与环境配置说明.md`；
依赖清单见 `requirements.txt`。

---

本项目包含两个并列的子项目，**目录结构与开发规则完全一致**，唯一区别是目的：

```
GW_ORF_研究项目/
├── 手征ORF计算_主线/        ← 本项目的核心目标：在PRD论文精确留数方法的基础上，
│                             加入JCAP论文的手征(圆偏振)物理设定，推导手征ORF的
│                             精确解析表达式，是全新的、尚未有人做过的计算
│
└── PRD强度ORF复现_副本/      ← 方法论验证副本：不涉及手征，只是把PRD论文
                              (Hu et al. 2025) 原文里已经发表的强度ORF结果
                              重新推导一遍，确认"留数定理+sympy"这套计算方法
                              本身是可靠的、可以复现已发表结果的
```

## 为什么需要一个"复现副本"

手征ORF计算是全新的、没有标准答案可以对照的计算。为了确认我们的计算方法
（坐标系选取、复变量代换、留数定理应用、sympy化简技巧）本身没有系统性错误，
最可靠的办法是先用同一套方法去复现一个**已知正确答案**的问题——也就是PRD论文
本身已经发表的强度ORF精确解。如果副本能够独立复现出PRD论文的结果（比如
退化到Hellings-Downs曲线、与小天线近似在低频吻合等），就能大大增强我们对
主线手征计算方法可靠性的信心。

## 两个子项目的结构完全一致

都遵循相同的"阶段-组件-性质"三层目录结构和调用规则，具体规则见各自
文件夹内的 `README.md`。这样做的好处是：任何时候想对照"强度版是怎么算的、
手征版对应哪一步"，直接在两个文件夹间用完全相同的路径去找就行，不需要
重新学习一套新的目录逻辑。
