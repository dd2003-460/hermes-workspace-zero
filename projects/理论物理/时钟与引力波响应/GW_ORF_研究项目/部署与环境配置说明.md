# 本地部署与环境配置说明

## 一句话总结

**本项目只依赖 4 个第三方库**：`numpy`, `scipy`, `sympy`, `mpmath`。没有任何
GPU、编译器、C扩展或特殊系统依赖，任何装了 Python 3.8+ 的机器（Windows/
macOS/Linux 均可）都能跑。

## 推荐流程（三选一，任选其一即可）

### 方式一：一键自检脚本（推荐，最省心）

```bash
cd GW_ORF_研究项目
python3 setup_check.py            # 只检查现状，不做任何改动
python3 setup_check.py --install  # 检查 + 自动 pip 安装/升级缺失或过旧的库
```

这个脚本会做四件事，每一步都有清晰的 ✅/❌/⚠️ 提示：
1. 检查 Python 版本（要求 >= 3.8）
2. 检查 numpy/scipy/sympy/mpmath 是否已安装、版本是否够新
3. 对每个库做一次"冒烟测试"——不只是 import 成功，还会实际跑一个真实的
   小计算（比如用 sympy 算一个留数、用 mpmath 算一个指数积分函数值），
   确认库的核心功能是真的可用，不是"装了但装坏了"
4. 实际运行项目里4个有代表性、跑得快的脚本，确认整条"代码→依赖库→输出
   结果"的链路真的能跑通（不只是能import）

如果一切正常，最后会看到：
```
🎉 全部检查通过！环境已就绪，可以运行本项目下的全部脚本。
```

### 方式二：用 requirements.txt 手动安装

```bash
cd GW_ORF_研究项目
pip install -r requirements.txt
```

### 方式三：手动逐个安装

```bash
pip install numpy scipy sympy mpmath
```

## 常见问题排查

**Q: pip install 很慢或者超时怎么办？**
如果所在网络环境访问 PyPI 官方源较慢，可以换用国内镜像源，例如：
```bash
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

**Q: 提示 "python3: command not found"？**
Windows 系统可能需要用 `python` 而不是 `python3`：
```bash
python setup_check.py --install
```

**Q: 某些脚本运行报错提示找不到 `.pkl` 文件？**
项目设计上每个"组件"文件夹是自包含的——"具体计算"产出的中间结果
（`.pkl`）会被手动拷贝一份到同级的"数值验证"文件夹里。如果你把某个脚本
单独复制到别的地方运行，会因为找不到同目录下的 `.pkl` 文件而报错。
**解决方法：保持完整的目录结构，进入脚本所在的原始文件夹里运行，不要
单独抽出某个 .py 文件。**

**Q: 运行涉及 `scipy.integrate.dblquad` 的脚本（比如组件C、组件D的部分
数值验证脚本）比较慢，正常吗？**
正常。这些脚本做的是二重数值积分作为"终极黄金标准"验证，通常需要
十几秒到几分钟不等（具体见各脚本的 docstring 里标注的用时）。这是
数值积分方法本身的计算量决定的，不是代码效率问题。

**Q: 想验证环境是否支持复数高精度计算（mpmath）？**
`setup_check.py` 的冒烟测试已经包含了这一项（测试 `mpmath.ei()` 函数），
如果这一步显示 ✅，说明没问题。

## 项目运行方式提醒

- 每个脚本都设计为"自包含、可独立运行"——进入脚本所在文件夹后直接
  `python3 脚本名.py` 即可，不需要设置 PYTHONPATH 或安装本项目为一个包。
- 建议阅读顺序：先看 `README.md`（总入口），再看想了解的组件下的
  `说明.md`，最后按"推导 → 具体计算 → 数值验证"的文件编号顺序阅读/运行
  该组件下的脚本。
- 各脚本 docstring 顶部都标注了【性质】【计算的量】【状态】【依赖】，
  运行前可以先看一眼，了解这个脚本是做什么用的、依赖了哪些上游产出。
