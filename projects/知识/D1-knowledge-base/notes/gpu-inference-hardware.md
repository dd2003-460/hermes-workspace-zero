# GPU 推理硬件: 为什么型号只解释一半性能

我按"给一个感兴趣但没学过的人讲"的标准写。素材是我自己 2026 年 4-9 月跟 AI 讨论 GPU 选型的四篇完整对话档案（2018 行选型流程 + 844 行性能报告 + 610 行算力误区 + 819 行 KV 方案），每个块讲清是什么、为什么、边界在哪，关键声明带 conf。

## A. 概念块

### 1. decode 为什么是内存带宽瓶颈
- **是什么**: LLM 逐 token 生成（decode）时，每生成一个 token 都要把全部权重从显存搬一遍。权重 14GB、带宽 1TB/s，理论上限约 70K token/s，算力（FLOPS）根本用不满。
- **为什么重要**: 所以选型第一指标不是 FLOPS 是显存带宽，V100 的 900GB/s 和 4090 的 1008GB/s 差得不大，但 V100 要 4 张卡才装得下大模型。
- **边界**: prefill（处理输入 prompt）是计算密集型的，那边 FLOPS 才重要。同一个模型 prefill 和 decode 的瓶颈在不同硬件维度上。conf 0.95

### 2. TP 分片：KV cache 每卡只存 1/4
- **是什么**: tensor parallel 4 卡跑 64 heads 的模型，KV cache 按 head 分片。GPU0-3 各存 heads 0-15/16-31/32-47/48-63。总 KV 40GB 时每卡只占 10GB，不是 40GB。
- **为什么容易搞错**: 直觉会以为每张卡都存全量 KV。实际分片后每卡显存压力是 1/4。这是 4×V100（4×16GB=64GB）能跑 27B 模型的根本原因。
- **边界**: 代价是每层都要 all-reduce 通信。传的是 hidden state + attention 结果，不传整个 KV。卡越多通信占比越高，PCIe 会先于显存成为新瓶颈。KV 命中是 token index → block index → 显存地址的直接定位，常数时间接近 0，不是数据库式检索。conf 0.9

### 3. TCO 框架：4×V100 为什么是性价比陷阱又是真便宜
- **是什么**: 4 张二手 V100 整机 ¥1w-1.28w，低于任何现代卡的入场价。单位 token 成本 ¥3.1e-8，4090 是 ¥1.5e-8。但漏算三个变量：功耗（4 卡 1000W vs 4090 450W，24h 满载差 ¥4800/年）、稳定性（老卡故障率 + 调试时间）、机会成本（单机吞吐天花板卡住扩展）。
- **为什么核心问题是"跑多久"**: 跑 3-6 个月 V100 便宜，跑 1-2 年 4090 总成本更低。V100 是低 CapEx 套利，4090 是高效率长期资产，不是谁好谁坏。
- **边界**: 这个对比只适用于"同一台机器上换卡"的场景，不适用于"加一台机器"。多机调度时 4 卡老机的运维成本会进一步放大。conf 0.85

### 4. "GPU × 精度 × backend × 长上下文"组合比型号重要
- **是什么**: 同一块 RTX PRO 6000 96GB 跑 Qwen3.8-27B 实测：FP8 时 1.4K 上下文 6265 tok/s，177.4K 时掉到 3906。换 NVFP4 同卡快 15-50%（177K 时 4496 vs 3906）。5090 跑 NVFP4 长上下文：2K → 8.8K、200K → 4.2K tok/s。16-64 并发下 aggregate 仍保持 ~9K/s。
- **为什么**: 量化方案（FP8/NVFP4/4bit）决定能装多少、跑多快；backend（SGLang/MLX/vLLM）决定 kernel 质量和调度；长上下文改变 prefill/decode 的比例。型号只是其中一个轴。
- **边界**: 所以"哪张卡最值"没有唯一答案，只有"哪个组合在我的负载下最值"。我的负载是长上下文 + 中并发 + solo，组合空间就小得多。conf 0.9

### 5. 线性注意力改变内存公式
- **是什么**: Qwen3.8-27B 不是纯 Transformer。64 层里 16 层 full-attention、48 层 GDN（gated delta net，线性注意力）。线性注意力层的"KV"不随序列长度增长，存固定大小的状态矩阵。
- **为什么 48GB 能跑 226K**: 默认 mamba-full-memory-ratio=1.0，按全量分配线性层状态，浪费显存。改成 0.2 后占用降下来，PRO 5000 48GB 就能做 226K 上下文。单请求 FP8 prefill 还能维持 ~5K tok/s。
- **边界**: 这是混合架构的特例，纯 Transformer（如 LLaMA 系）没有这个旋钮。显存公式要分开算 attention 部分和状态部分。conf 0.8

### 6. KV cache 复用：从黑盒到可调度资源
- **是什么**: 同一 prefix 的 KV 算过一次就能复用，不用重算 prefill。但 LM Studio/omlx 把 KV 当黑盒，不做 chunk 级控制。要做复用必须下沉到 mlx-lm 层，自己接管 KV 生命周期。
- **四条路径**: ① 截断 KV（sliding window/chunk cache）② RoPE rebase：MLX 的 RoPE 是显式函数，存未旋转的 k_raw，用时再 apply_rope 到新位置，KV 才能跨位置复用 ③ 分页：仿 vLLM PagedAttention，KV 切成 page，复用靠引用不靠复制 ④ 策略层：KVCacheManager 做 match（精确 hash/语义 embedding/按 system-tool-user 分块）→ assemble → update。
- **为什么**: 我这种"上百个 idea 验证"的负载，system prompt 和工具描述每轮都重复。prefix 复用能把重复 prefill 直接砍掉，单位 token 成本降一大块。
- **边界**: 工程量大。solo 做 ②③ 已经是"自己写推理引擎"的量级。conf 0.7

### 7. 边界与未解问题
- ① 长上下文下 decode 掉速（177K 时 3906 vs 1.4K 时 6265）是 KV 读取变慢还是注意力计算变慢，我没拆解过，conf 0.5。
- ② NVFP4 在 177K 长上下文没崩（4496 vs FP8 的 3906）。但精度损失对任务质量的影响没测过，只有吞吐数据。conf 0.5。
- ③ 5090 魔改（改供电/显存）的可靠性没有数据，档案里只到"能做"，conf 0.4。

### 8. 可证伪预测（带判死条件）
- **预测**: 我的负载（Qwen3.8-27B、上下文 30K-226K、并发 ≤ 8）下，PRO 5000 48GB + FP8 + SGLang 的 ¥/226K 有效 prefill tok/s 应低于 PRO 6000 96GB + NVFP4 的 60%。原因：96GB 卡贵 ~2 倍，而我的上下文装得下 48GB。conf 0.6
- **判死**: 若实测 PRO 5000 的 ¥/tok 高于 PRO 6000 的 60%，则"48GB 够用、96GB 是过剩购买"的假设被拒绝，下次采购按 96GB 走。
- **为什么这条最硬**: 它把"买哪张卡"从感觉变成一次可测的横评，跑一个下午就知道。

## B. 成璐视角

**判断**: 我的核心判断: GPU 选型的真问题不是"哪张卡快"，是"我的负载（长上下文 + solo + 中并发）在哪个 型号×精度×backend 组合下 ¥/tok 最低"。型号只解释一半性能，剩下的一半在实现和组合里。我猜 96GB 卡对我是过剩购买，48GB 是我的最优点，这条预测可以一周内验证。conf 0.7

**自我质询**: 我"48GB 够用"的判断可能错——如果我的上下文经常突破 226K，或者并发上到 32+，48GB 会先撞墙。我目前的数据只覆盖到我的真实负载，没覆盖"负载长大"的场景，标 conf 0.6。

**动机**: 我要在本地跑得起自己的推理栈（上百个 idea 验证 + KV 复用 + 多 agent 并行），硬件是整个栈的地基。地基买错了，上面的 agent 架构做得再好都被 ¥/tok 卡死。

**新 idea**: 我列的下一步: ① 跑 §8 的横评（PRO 5000 vs PRO 6000，同模型同负载，只算 ¥/tok）② 给 mlx-lm 实现路径 ② RoPE rebase，先测 prefix 复用能砍多少重复 prefill ③ 把 4×V100 当"离线 batch 验证机"重新定位，不和主力卡比延迟。

**明确砍掉**: 我砍掉: 不买 96GB 之前先验证 §8 / 不碰 5090 魔改（可靠性无数据）/ 不自己写完整推理引擎（先做 KV 复用策略层，量级小一个数量级）。

**一句话**: 我的总结: decode 是带宽瓶颈所以看 GB/s 不看 FLOPS，KV 按 head 分片所以 4 卡显存压力是 1/4，TCO 核心是"跑多久"，组合比型号重要，线性架构改内存公式，KV 复用是 solo 负载的 ¥/tok 杀手锏。
