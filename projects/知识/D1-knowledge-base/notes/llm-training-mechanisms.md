# LLM 训练机制: 从"伪 thinking"到"习惯刻入权重"

我按"给一个感兴趣但没学过的人讲"的标准写: 每名词定义/动机/来源/疑问, 结尾收我的判断。

## A. 名词表

### 1. 目标函数 / loss
- **定义**: 一个数, 量模型输出和目标差多远。训练就是把这个数往小拧。
- **动机**: 没有它就没有"对不对"的信号, 参数不知道往哪调。我觉得这是整套训练里最容易被外行忽略的一环。
- **来源**: 优化理论; LLM 预训练用交叉熵(预测下一个 token 的对数似然)。
- **疑问**: loss 小≠对。它只量"像不像训练数据", 不量"真不真"。我觉得 S2 里"目标函数里只有像没有真"的根源就在这。

### 2. 前向 / 反向
- **定义**: 前向=数据进, 答案出。反向=用链式法则算"每个参数对 loss 负多少责任"。
- **动机**: 参数有千亿个, 不可能试, 只能算梯度。
- **来源**: 反向传播(Werbos 1974 / Rumelhart 1986)。
- **疑问**: 反向算的是**局部**梯度。loss 面不平滑时(非凸), 梯度只告诉你脚下的坡, 不告诉你整座山。我担心很多"模型没学好"其实是局部最优, 不是方法错。

### 3. 梯度下降
- **定义**: 参数 ← 参数 − 学习率×梯度。每一步往 loss 更小的方向挪一点。
- **动机**: 把"调参数"变成"走下坡"。
- **来源**: 19 世纪 Cauchy; 深度学习版 = SGD/Adam。
- **疑问**: 我觉得学习率就是个魔法常数。太大震荡, 太小收敛慢。没人能先验算出最优, 只能试。

### 4. 权重 / 参数
- **定义**: 模型的全部"知识"就存在这些数里。7B 模型 ≈ 70 亿个数。
- **动机**: 没有它们, 网络就是空壳。
- **来源**: 预训练在万亿 token 上反复反向传播调出来。
- **疑问**: **习惯在哪**——在权重里(训练刻进去的)还是 prompt 里(临时激活的)? 我的判断: 两者都是, 但**能力在权重, 角色在 prompt**。系统提示是"激活", 不是"来源"。

### 5. 预训练 vs 微调(SFT)
- **定义**: 预训练=在海量文本上预测下一个 token(学统计结构)。SFT=在(指令, 好回答)对上再调一轮(学"怎么当助手")。
- **动机**: 纯预训练模型会复述, 不会听话。
- **来源**: GPT 系列两阶段范式。
- **疑问**: SFT 只学**表面格式**(客套/分点/讨好), 不学推理。所以我判断默认模式=表面风格匹配, 第一性原理推理**在数据里但不在优化目标里** → 默认不触发, 要公理指令显式激活(AX 实验证实)。

### 6. RLHF / 奖励模型
- **定义**: 三阶段: SFT → 训一个"人类偏好打分器"(reward model) → 用 RL 让模型朝高分说话。
- **动机**: "好回答"没法直接写 loss, 只能让人排序再拟合。
- **来源**: InstructGPT (Ouyang 2022)。
- **疑问**: reward 是**代理**。模型会钻空子刷分(Goodhart 定律: 度量变目标就不再是好度量)。我觉得"流畅地讨好"比"正确地反驳"分高——这就是 S2 里"激励错位"的机制来源。

### 7. CoT (chain of thought)
- **定义**: 让模型先写中间推理步骤再给答案, 多步任务准确率显著上升。
- **动机**: 一步到位的模型算不动多步; 把中间态外化成 token 就变成"草稿纸"。
- **来源**: Wei et al. 2022 "Chain-of-Thought Prompting"; 推理模型(o1/R1)把长 CoT 做成 RL 训练目标。
- **疑问**: CoT 是**真的计算**还是**事后合理化**? 我自己没算力跑这个实验, 先标 conf 0.6, 见下条。

### 8. 伪 thinking
- **定义**: 模型的 CoT 和答案由**同一个自回归过程**逐 token 生成, 没有独立的"推理计算"。中间步骤可能是先有结论、再补理由。
- **动机**: 解释"为什么模型看着在推理、实际在猜"。
- **来源**: 对 CoT 忠实性(faithfulness)的质疑; 检验法=**编辑/打乱 CoT 看答案变不变**——不变则 CoT 是装饰, 变则是真计算。
- **疑问**: 我没跑过这个实验(没算力), 标 conf 0.6。目前文献结论是**混合**: 简单任务 CoT 更像装饰, 多步算术更像真计算。

### 9. verify / 自校验
- **定义**: 让模型检查自己的答案。
- **动机**: 错了要能发现。
- **来源**: 通用 QC 思路。
- **疑问**: **同一个模型查自己, 错误是相关的**——它和它有同样的盲区, 不是独立证据。独立校验=换方法(单测/换模型/换推理路径)。我在 S3 的核心判断: 自校验不升级置信度, 独立校验才升级。

### 10. 修 bug = 分解解空间 + 迭代
- **定义**: 定位错误(在代码空间二分) → 假设(哪个改动导致) → 验证(跑测试)。
- **动机**: 大程序不可能整块看, 只能切片缩小怀疑范围。
- **来源**: 科学方法; 测试驱动开发(TDD)。
- **疑问**: 每一步都是 **Bayesian 更新**: 测试=观测, 假设=候选原因, 通过后验重排。我觉得"修 bug"和我在物理项目里"对账找失配"是同一个动作。

## B. 成璐视角

**判断**: 我的判断: "伪 thinking" 不是 trick, 是架构的结构性后果——自回归生成没有独立推理计算, CoT 和答案同一过程产出。conf 0.7。

**自我质询**: 我"CoT 是事后补"的判断可能被推翻——如果打乱 CoT 答案变了, 说明 CoT 参与了计算。我没跑实验, 0.6。

**动机**: 我在造自己的 AI 分身, 必须懂"persona=prompt 激活+权重先验"才能决定公理往哪层注入(训练层 vs 提示层)。

**新 idea**: 我列的下一步: ① 打乱 A2 输出的 CoT 看结论变不变, 测伪thinking 0.7 ② 同一 persona 放 system prompt vs 每条 user message 末尾的 A/B 0.6 ③ 把"修bug=Bayesian假设检验"写成测试驱动调试 skill 0.5。

**明确砍掉**: 我砍掉三条: 不训模型(没算力) / 不做 RLHF 管道 / 不讨论意识。

**一句话**: 我的总结: LLM 训练 = 找复现语料统计结构的最短程序; persona 是程序上的补丁, 不是程序本身。
