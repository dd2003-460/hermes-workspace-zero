# 对抗核验任务书模板（跨项目通用）

> origin: ai · 2026-11-02 · 从 pfb TASK-adversarial-check.md + decomp T8-C3-adversarial-check.md 两份实战任务书提炼
> 触发：任何评分协议/实验方案/统计判据定稿前，派 arena 做对抗复核时使用。
> 目的：让反方 agent 用固定结构找漏洞，Lead 按回执逐条裁定，避免"自己审自己"的盲区。

## 使用方式

1. 复制本模板 → 填【】占位符 → 存到目标仓 `tasks/<对象>-adversarial-check.md`
2. 按 sop/arena-loop-pipeline.md §3.1 会话台账选该仓既有 arena 会话派发（不新开）
3. agent 回执落盘后，Lead 逐条裁定 PASS/FAIL-with-fixes，裁定结果写进回执文件尾部
4. 验收门禁：回执 JSON 含全部质询方向的结论 + 总体判定，缺项 = 验收不过

## 模板正文

```markdown
# 对抗核验任务书 — 【对象名称】

> origin: ai · 【日期】 · 供 arena agent mode 执行
> 对象：【被核验对象的文件路径 + 一句话定位】
> 角色：你是审稿人，任务是**找这个【对象类型】测不出东西或测出假东西的地方**。不是夸它设计得巧。

## 背景（你需要的最小上下文）

- 【项目一句话】：为什么做这件事、要证明什么
- 【前置证据】：已有哪些相关实验/数据（路径），它们证明了什么、没证明什么
- 【本次对象的角色】：它在整个链条里是第几环、下游谁依赖它的输出
- 【关键数字】：当前核心指标的值 + 口径限定（聚合方式/tie-break/judge 族）

## 六个质询方向（逐条给结论 + 证据）

### Q1 循环论证检查
【对象】的核心判据是否依赖了和它同源的输入（gold 树/标注/参考实现也是作者写的）？
找出所有同源依赖，给出解耦方案（或证明不可解耦并说明残余风险）。

### Q2 维度独立性 / 混淆变量
各评分维度（或实验条件之间）哪些实际上高度相关/存在未控制差异？
相关的话分开报还有意义吗？用已有数据做相关性预检——能算的先算，不能算的说清需要什么数据。

### Q3 统计功效
每个配置/条件的样本量能否支撑计划中的判读（显著性/方向性）？
需要多少样本才有足够 power？当前设计的最小可检测效应是多少？

### Q4 测量噪声 vs 信号
裁决工具本身（judge/断言脚本/人工打分）的噪声有多大？会不会淹没被测效应？
有没有阳性对照/阴性对照验证过测量链路的灵敏度？

### Q5 选择-验证同源偏差
用于选参数/选组件的数据和用于验证的数据是不是同一批？
是否存在 hold-out 需求？当前设计下哪些结论会被同源污染？

### Q6 降级与边界行为
当输入缺字段/超出适用范围时，【对象】的行为是什么？
静默跳过还是显式报错？降级路径有没有被测试过？

## 交付要求

- 逐条给出：漏洞是否成立 / 严重度（高/中/低）/ 具体修正建议
- 最后给总体判定：PASS（可直接用）/ PASS-with-fixes（列出必改项）/ FAIL（根本缺陷）
- 不要泛泛而谈，每条要落到可操作的修改
- 回执格式：JSON，schema 见下

## 回执 schema（agent 必须产出）

{
  "kind": "adversarial_check",
  "target": "<对象路径>",
  "observed_at": "<ISO 8601 带时区>",
  "checks": [
    {"id": "Q1", "finding": "<结论>", "severity": "high|medium|low|none",
     "evidence": "<文件路径或计算过程>", "fix": "<可操作修改或 null>"}
    // Q2-Q6 同上
  ],
  "verdict": "PASS|PASS_WITH_FIXES|FAIL",
  "mandatory_fixes": ["<必改项列表，PASS 时为空>"]
}
```

## Lead 裁定规则（回执回来后）

- verdict=FAIL → 对象不得进入下游使用，先修再重核
- verdict=PASS_WITH_FIXES → 必改项逐条落实后，只重跑受影响质询方向（不全量重核）
- verdict=PASS → 对象放行，回执归档到对象同目录 `receipts/`
- 任一条 severity=high 且 fix 涉及核心判据 → 无论总体判定如何，该条必须先解决
