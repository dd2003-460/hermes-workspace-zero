# 撞车调研 SOP（Collision Research SOP）

> origin: ai · 2026-11-15 · 成璐指令："这玩意可以作为科研的调研/idea/撞车相关sop吗"
> 来源：T-PR-16 实战（4 个主张 × 84 组 arXiv 查询 × 四象限覆盖）
> 用途：任何研究主张/idea 在写论文新颖性声明前，必须先过本 SOP。

---

## 0. 为什么需要这个 SOP

撞车调研 = 查"我们想做的事，有没有人已经做过了"。

**为什么必须在写论文前做**：新颖性声明是论文的核心卖点。如果核心卖点被人占了，整篇论文的叙事要改。T-PR-16 的 C4（压缩阶梯）就是例子——"expansion tax" 这个术语零命中，但 DeComp2 用完全不同的词汇（C_circ + C_Kol）表达了同一构念。如果只做术语搜索不做构念核验，会漏掉这种撞车。

**核心教训（T-PR-16 实证）**：术语零命中 ≠ 构念零命中。"expansion tax" 零命中，但"描述复杂度 + 展开代价"这个构念在 2024 年就被 RDT 论文（2405.05294）提出来了。所以本 SOP 的主场是**构念层核验**，术语层只做辅助。

## 1. 触发条件（什么时候必须走这个 SOP）

| 触发条件 | 例子 |
|----------|------|
| 论文里要写"我们首次提出 X" | "我们首次将 K 复杂度引入 LLM 分解树" |
| idea 从讨论捕获进入实验阶段 | #47 从"讨论捕获"进入"消融完成" |
| 对标物检索后仍不确定新颖性 | G2 核心 claim 无直接撞车，但窗口收窄中 |
| 投稿前最终核验 | 投稿前重跑本调研（滚动核验纪律） |

**不触发的情况**：纯工程实现（没有理论主张）、已有明确先例且只需引用（不需要判定撞车）。

## 2. 输入（开始之前要准备好什么）

| 输入 | 格式 | 来源 |
|------|------|------|
| 主张清单 | 每条主张：编号 + 一句话描述 + 创新声明定位 | lit-survey/IDEA-INDEX.md 或 tasks/ 任务书 |
| 已有撞车结论 | 已闭环的撞车报告（不必重查） | research/collision-*.md |
| 检索面声明 | 本轮查哪些渠道（arXiv/GitHub/ACL/OpenReview） | 本 SOP §4 |
| 判据定义 | 什么算撞车、什么算 related work、什么算无先例 | 本 SOP §5 |

**缺失处理**：主张描述不够具体（"我们做了 X"但 X 没有操作定义）→ 先补操作定义再开始检索。没有操作定义的主张无法检索，因为不知道该搜什么。

## 3. 检索方法（四象限 + 构念层）

### 3.1 四象限覆盖

每个主张查四个象限，确保不遗漏：

| 象限 | 含义 | 查什么 | 例子（C4） |
|------|------|--------|-----------|
| 权威象限 | 高引/大厂/顶会脉络 | 该领域最权威的 3-5 篇 | RDT（2405.05294）、Kolmogorov 结构函数（2504.09597） |
| 小众象限 | 小团队/新玩法 | 该领域边缘但活跃的工作 | SkillZip（2608.11079）、RIMRULE（2601.00086） |
| 最近轨迹 | 2026-09~11（窗口期风险） | 最近 3 个月的 arXiv 提交 | 2611.11447（propagator 顺序学习） |
| 过去轨迹 | 2024~2026-03 | 历史积累 | DoG（2410.18415）、MADIL（2505.01081） |

**为什么四象限**：只查权威象限会漏掉小众圈正在填的空白（C4 的小众象限是活跃施工区）；只查最近轨迹会漏掉历史积累（C4 的根在 2024 年）。

### 3.2 构念层核验（主场）

**核心规则：找到最近的构念先例 → 顺着引用图滚。**

不是搜关键词，而是：
1. 找到最接近的 1-2 篇论文（按构念相似度，不是按关键词匹配）
2. 读它的 related work 节 → 它引了谁
3. 查谁引了它（Google Scholar / Semantic Scholar）
4. 对每个新发现的论文重复 2-3

**为什么**：同一构念可以用完全不同的词汇表达。"expansion tax" 和 "C_circ" 是同一个东西，但关键词搜索永远找不到关联。引用图能跨词汇找到。

### 3.3 术语层精确检查（辅助）

对每个主张的特征短语做 arXiv `all:"..."` 精确搜索：
- 零命中 → 记录为"术语独占"（辅助证据，不是结论）
- 有命中 → 逐条判断是否真正相关

**T-PR-16 教训**："expansion tax" 零命中，但构念被占。术语零命中只作辅助证据，主场用构念层。

### 3.4 检索渠道

| 渠道 | 用途 | 限制 |
|------|------|------|
| arXiv API（https://export.arxiv.org/api/query） | 主渠道，按 submittedDate 降序 | 只覆盖预印本，不覆盖在投未挂 arXiv 的工作 |
| GitHub search API | 代码/实现层面 | 未鉴权 10 req/min，code search 需要 auth |
| ACL Anthology | NLP 顶会正式版 | 不覆盖非 NLP 领域 |
| OpenReview | 在投评审中稿件 | 只覆盖 ML 顶会 |
| Google Scholar / Semantic Scholar | 引用追踪 | 手动操作，无 API |

**盲区声明**（必须写进报告）：
- 未查 ACL Anthology / NeurIPS 正式版 / OpenReview 的评审中稿件
- 关键词组合不可能穷尽表述变体
- 未查非英语文献
- 在投未挂 arXiv 的工作完全在盲区

## 4. 判定标准（什么算撞车）

### 4.1 三级判定

| 判定 | 标准 | 后果 |
|------|------|------|
| 🔴 撞车 | 有人做了**同一机制**且**结论可比** | 新颖性声明必须改：从"我们提出"改为"引用后承接" |
| 🟡 部分已有 | 机制的大方向有人测过，但**特定组合/场景**无人测 | 增量收窄：从"我们提出 X"改为"X 在 Y 场景下未被测过" |
| 🟢 无先例 | 四象限 + 构念层 + 术语层全部无命中 | 新颖性声明可保留，但必须附检索面声明 |

### 4.2 判据细化（按主张类型）

| 主张类型 | 撞车标准 | 例子 |
|----------|----------|------|
| 方法主张（"我们提出方法 X"） | 有人用同一方法解决同一问题 | C4：DeComp2 用 C_circ + C_Kol 做分解优化 |
| 现象主张（"我们观察到现象 Y"） | 有人系统测过同一现象 | C1：置信度作为独立维度（2604.05952 测过） |
| 定位主张（"我们的研究定位是 Z"） | 有人用同样的理论框架解释同一行为 | C2：DecompressionLM 用生成式解码读出概念图 |
| 方法论主张（"我们的归因方法 W"） | 有人用同一归因方法做同一类实验 | C1：prior on/off 对照（2603.22161 因果证明） |

### 4.3 置信度标注

每个判定带 conf（0-1）：
- 0.9+：多篇独立工作做了同一事，结论一致
- 0.7-0.9：单篇直接撞车，或多篇间接撞车
- 0.5-0.7：构念相似但领域不同，或判定标准本身有模糊性
- <0.5：弱相关，只算 related work

**conf 低时的处理**：标注"判定本身有模糊性，换一个判定人可能得到不同结论"，交给 Lead/用户决策。

## 6. 撞车后的应对（不是沮丧，是机会）

**核心心态（成璐 2026-11-15 指令）**：有基础的工作不要感觉碰上了就沮丧，反而借此机会：
1. **描述原始 idea**：我们的直觉是什么、为什么想到这个
2. **学习借鉴前人工作**：他们做了什么、我们站在哪里
3. **social 展示初步构想和初步成果**：发邮件、写博客、发预印本
4. **DOI 占坑**：arXiv 预印本有 DOI，先挂上去占时间戳

### 6.1 撞车后的决策树

```
撞车判定
├── 🔴 完全撞车（同一机制 + 同一领域）
│   ├── 我们的增量 = 0 → 归档 idea，写进 notes（不删，是原始直觉）
│   └── 我们的增量 > 0（特定场景/参数/应用）→ 收窄声明，引用后承接
├── 🟡 部分已有（大方向有人测，特定组合无人测）
│   ├── 增量收窄到特定组合 → 继续做，声明改为"X 在 Y 下未被测过"
│   └── 增量太窄（不值得单独成文）→ 并入其他主张的 related work
└── 🟢 无先例
    ├── 统计够（n≥10/组）→ 直接写新颖性声明
    └── 统计弱（n<10）→ 标 pilot effect estimate，扩样本后再声明
```

### 6.2 DOI 占坑流程

1. 写一个简短的 preprint（2-4 页）：原始 idea + 初步结果 + 与先前工作的关系
2. 挂 arXiv（cs.AI / cs.CL / cs.LG 按领域选）
3. arXiv 自动分配 DOI（10.48550/arXiv.<id>）
4. 记录 DOI 到 IDEA-INDEX 对应行

**为什么**：时间戳是新颖性的最终证据。即使后来被人做了同一事，"我们 2026-11 挂的 preprint 比他们 2027-01 的论文早"就是占坑成功。

### 6.3 Social 展示

| 渠道 | 内容 | 时机 |
|------|------|------|
| arXiv preprint | 原始 idea + 初步结果 + 与先前工作关系 | 撞车判定后立即 |
| 邮件（给相关领域研究者） | "我们注意到您的工作 X，我们的 idea Y 与它相关，初步结果是 Z，想听听您的看法" | preprint 挂出后 1 周内 |
| 博客/技术笔记 | 大白话版本：为什么想到这个、撞到了什么、下一步 | preprint 挂出后 2 周内 |

**邮件模板**：
```
Subject: Related work: <我们的 idea> vs your <他们的论文>

Hi <名字>,

I'm working on <一句话描述我们的 idea>. I noticed your paper
<arXiv ID> which addresses <他们的贡献>. Our preliminary results
suggest <初步结果>. I'd love to hear your thoughts on whether
<具体问题>.

Best,
<名字>
```

## 7. 滚动核验纪律

- **投稿前重跑**：本调研不是做一次就完。投稿前必须重跑（窗口期风险：最近轨迹象限可能已变化）
- **引用追踪**：从撞车论文反向滚雪球（它引谁、谁引它），比关键词更可靠
- **术语零命中 ≠ 构念零命中**：这条教训写进 SOP，每次调研前读一遍

## 9. 已知局限

1. **arXiv 盲区**：在投未挂 arXiv 的工作完全在盲区。缓解：查 OpenReview + ACL Anthology。
2. **关键词不可能穷尽**：同一构念可以用完全不同的词汇表达。缓解：构念层核验（引用图追踪）是主场。
3. **非英语文献**：未查。缓解：如果主张涉及非英语领域，手动补查。
4. **判定模糊性**：conf <0.6 的判定本身有模糊性，换一个判定人可能得到不同结论。缓解：标"需 Lead/用户决策"。
5. **时间窗口**：本 SOP 的检索面是执行时刻的。投稿前必须重跑。
