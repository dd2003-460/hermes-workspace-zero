# 交叉复核打分 SOP（bench 大类 · 2026-10-31）

> 来源：成璐 2026-10-31 指令 + pfb rubric-v3 实战经验（κ 审计、erratum-27、jaccard-m5）。
> 适用：任何"多个裁判/口径给同一对象打分"的场景——AI 评分器一致性、人工评审、多模型交叉验证。

## 核心原则（按顺序执行）

### 1. 统一标准，分列记录

所有裁判用**同一份 rubric**（评分维度定义 + 档位判据），但每个维度独立记一列分数。
不许把多维度压成一个总分再比——总分丢失了"哪个维度分歧"的信息。

| 样本 | 维度A | 维度B | 维度C | 总分(仅参考) |
|------|-------|-------|-------|-------------|
| s1   | 3     | 2     | 4     | 9           |
| s2   | 3     | 4     | 2     | 9           |

s1 和 s2 总分相同但模式完全不同——分列才能看见这种差异。

### 2. 打分理由必须可追问到数学边界

每条分数附理由文本。理由的质量判据（严格版）：

- **唯一性**：给定 rubric + 样本，两个理性裁判应得出同档。若理由允许两种读法 → rubric 有歧义，先修 rubric 再打分。
- **充分性**：理由必须引用样本中的具体证据（行号/原文片段），不接受"整体感觉偏上"。
- **必要性**：理由中每个断言都必须是判定该档所必需的——多余断言 = 噪声，会被下一个裁判误读为约束。
- **数学边界追问**：对每个判据问"为什么是这个阈值而不是相邻值？"答不出 = 判据是拍的，需要数据支撑或降级为软指标。例：Jaccard < 0.9 算重复——为什么不是 0.85？答：因为实测候选集重叠分布的拐点在 0.9（需附数据）。

### 3. 一致性度量选择（看分数特性）

**先做信度分析再选方法**：

| 分数特性 | 方法 | 理由 |
|---------|------|------|
| 二分类（过/不过） | Cohen's κ（2 裁判）/ Fleiss'κ（≥3） | 去瞎蒙基线后的真实一致度 |
| 有序档位（1-5）且临界附近波动小 | 加权 κ（线性权重）或连续化回归 | 相邻档差 1 比跨 3 档更可接受 |
| 连续值 | ICC(2,1) 或 Spearman ρ | 保留量级信息 |
| 临界值附近波动大（如 κ 在 0.59-0.61 间跳） | **连续值回归**：把档位映射到 [0,1] 连续标尺，拟合裁判间映射函数，残差即分歧 | 离散档位的量化噪声在临界处被放大，连续化消除人为切分 |

**连续化回归的具体做法**（成璐提的 log 平滑思路）：
- 若分数是概率/频率类（如命中率 p），用 log(p/(1-p))（logit 变换）拉开两端、压缩中间，再做裁判间线性回归。
- 若分数是计数类（如命中数 k/N），用 arcsin(√(k/N))（角度变换，方差稳定）。
- 回归斜率 ≈ 1 且截距 ≈ 0 = 两裁判尺度对齐；斜率偏离 = 系统性松紧差（一个裁判整体偏严）。

### 4. 同一题 vs 不同题

- **同一题（同一样本多裁判）**：要求信度。κ ≥ 0.6 或 ICC ≥ 0.75 为可接受；< 0.4 说明 rubric 本身有问题，不是裁判的问题。
- **不同题（跨样本）**：不要求一致，要求**正交**。不同维度测的东西应该独立。

### 5. 正交化的正确姿势（防粗暴合并丢信息）

**顺序：先保证完整 → 再分离正交部分 → 最后去重。**

1. **完整性优先**：所有维度的原始分数全部保留，不做任何合并。
2. **分离正交分量**：对维度分数矩阵做 PCA 或相关矩阵分解。前 k 个主成分解释 > 80% 方差时，用这 k 个成分替代原维度（降维不丢主要信息）。
3. **去重只删冗余**：两个维度相关系数 > 0.95 且语义可互换时，保留信息量大的那个（方差更大的），另一个标记为冗余但不删除（留溯源）。
4. **禁止的操作**：直接平均两个相关维度当"综合分"——这会把两个维度的共同噪声放大，同时抹掉各自独有的信号。

### 6. 离群值处理（erratum-27 教训）

- **先交叉复核再剔除**：任何与主流口径不一致的数字/分数，先用独立方法复算。复算一致 → 它是真离群（记录原因）；复算不一致 → 它是错误（勘误，走 erratum 流程）。
- **"最严格"的含义**：不是"按我的标准它一致"，而是"在所有可复现口径下它的归属是否稳定"。erratum-27 的教训：27 在任何口径下都复现不出来 = 起草期人工计数错误，不是口径选择问题。
- **意思相近的变体**（如中文数字"二十七"vs"27"、"约十三"vs"13"）：归一化规则必须在打分前预注册（写进 rubric），不能事后决定哪些算同一个 token。预注册格式：`等价类 = {27, 二十七, 27B(型号语境除外)}`，每类附排除条件。
- **后续未再现 = 确认剔除**：如果离群值在后续 N 轮（N ≥ 3）独立复算中从未出现，可以安全剔除，但要在 revision-log 里登记"何时发现、为何剔除、剔除后影响面"。

## 记录规范

每次交叉复核产出一个 receipt JSON：

```json
{
  "task": "描述",
  "rubric_version": "哈希或版本号",
  "judges": ["裁判1", "裁判2"],
  "scores_matrix": {"sample_id": {"dim_A": x, "dim_B": y}},
  "agreement": {"method": "cohen_kappa|icc|spearman", "value": 0.xx, "threshold": 0.6, "pass": true},
  "outliers": [{"item": "...", "reason": "...", "cross_check": "confirmed|error"}],
  "orthogonality": {"method": "pca|correlation", "retained_dims": [...], "dropped_dims": [...]},
  "observed_at": "ISO 8601"
}
```

存放路径：`bench/<domain>/receipts/<task>-<date>.json`
