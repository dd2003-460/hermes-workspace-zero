# 验证与结论引用 SOP（跨项目通用）

> origin: ai · 2026-10-31 · 从 pfb AUDIT-report + decomp arena-adversarial-review 两条对抗核验线提炼
> 触发：任何实验产出数字结论、评分协议定稿、对外宣称分数时必读。

## 1. 验收项 = 有没有人真的跑过（纸面协议防护力为零）

来源：pfb G4 S3——p̃ 多模型盲生成协议写在 DRAFT 里但消融没用它执行，"协议完整"被判定为风险未受控。

规则：
- 验收清单里每条防护机制必须附**实跑证据**（命令输出/回执文件路径），不附 = 该条视为不存在。
- "协议里写了没有"和"执行层跑了没有"是两个独立检查项，前者 PASS 不能替代后者。
- 降级运行（缺字段跳过维度）必须在回执里显式标 `degraded` + 跳过原因，不得静默。

## 2. 多 judge 必须异族（同族双判无隔离价值）

来源：pfb G2 F2(a)——两 judge 同底座 qwen3.8-27b，N-1/N-2 零命中高估在两 judge 下同时出现，同源共享偏差无法靠加 judge 消除。

规则：
- 独立性声明必须写清是**上下文独立**还是**家族独立**，两者不等价。
- κ/一致性统计的 judges 列表必须含模型族标识；同族 ≥2 个时 κ 数值只算上下文重复度，不算独立校验。
- arena battle 投票通道是当前唯一免费的异族多 judge 来源（投票揭示模型名）。

## 3. 统计设计先做功效分析（n=3 产不出显著性）

来源：decomp arena 复核 Q1——n=3 bootstrap CI 是退化区间（分位数必落在极差上），精确符号检验最小双侧 p=0.25，"显著"标签是 CI 启发式造出来的。

规则：
- 实验前预注册：效应量 Δ → 所需样本对数（σ≈2 时 Δ=2 需 ~11 对、Δ=1 需 ~35 对）。
- n < 8 的结果禁止打"显著"标签，只报点估计 + 区间 + "功效不足"声明。
- σ 基线本身也要带 n 和区间（σ 的 df=n-1，n=3 时 σ 的 95% CI 宽到无信息量）。

## 4. 引用统计量必须带口径限定

来源：pfb AUDIT finding #12/#13——top5_gold 1/5↔2/5 翻转纯由 tie-break 决定；per-run vs global 聚合口径下结论相反。

规则（强制限定语清单，引用时逐项核对）：
- [ ] 聚合口径（global / per-run）
- [ ] tie-break 规则（id 序 / 随机 / 无并列）
- [ ] judge 族构成（异族 N 个 / 同族上下文独立）
- [ ] gold 参照系（相对 Lead-gold ≠ 绝对构念效度）
- [ ] p̃/权重来源版本（orig / new / cross-judge）
缺任一项 = 该数字不得出现在对外文本中，只能出现在内部工件带完整注记。

## 5. 负面结果登记制度

来源：pfb AUDIT §5（15 条负结果合并去重）+ decomp T11（arena 把"显著"降级后原结论保留但改标签）。

规则：
- 每个 goal 收口时，证伪/不支持/被限定的假设必须写入负结果清单（格式：假设原文 → 判定 → 证据路径 → 来源 goal）。
- 去重标准：同一假设 + 同一证据 + 同一结论三条全同时才合并；限定语原文保留不缩写。
- 负面结果是资产不是垃圾：回炉不会让它们消失，它们构成"已知暴露面"的一部分。

## 6. 机判边界诚实登记

来源：pfb finding #14/#15——语义级重判和 κ 计算过程合规性都不可机判。

规则：
- assert-* 脚本的能力边界写进 docstring：能验什么（存在性/schema/数值复算）、不能验什么（过程合规/语义判断）。
- 不可机判的环节显式导出人工/multi-judge 任务入 queue，不留"看似已覆盖"的假象。

## 7. 配置错误 ≠ 架构结论（混淆变量检查）

来源：decomp arena 复核 Q2——B 与 C 同时差 5 个维度，其中 oracle 路由（INDEX 按已知问题手写）+ 配置错误（embed 语言）占了根因的 2/3，把配置错误包装成"Mem0 输给文件树"是最大推断跳跃。

规则：
- 对比实验收口前，列出两组之间**所有**差异维度（不只目标变量），逐条标注"目标变量 / 混淆变量 / 配置错误"。
- 混淆变量未控制时，结论只能写成条件句（"在 X 相同的前提下…"），不得写成架构判定。
- 配置错误类发现单独登记，不与能力结论混排。
